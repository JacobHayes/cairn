## Decision log

Appended by the implementer.

- Screens and addresses: `/journeys/<id>/list`, `/next`, and `/triage` (`?mode=decisions` is the walkthrough), each linked from a row of the journey's screens (`screens/JourneyNav.tsx`) that the canvas shows too. What each shows lives in its address as the canvas's does: the list's `flag`, `in`, `owner`, `state`, `kind`, `q`, `sort`, `group=container`; the next list's `sort`, `mine`, `kind`, `me` (prioritize for me); triage's `mode`, `mine`, `kind`. The journey creation hook is `walkthroughPath` (`acting/address.ts`): 5.5's creation flow navigates there once the journey exists.
- The engine answers every list and ordering: the list is the `list` projection (a page of 200 with its cursor), next and triage the `next` projection (triage always by rank), both over the tab's derivation in the derive worker, so nothing is filtered or sorted in TypeScript but grouping by container (each group where its first row falls in the sort order).
- Table component: a plain `<table>` in the design system's `.table`; no library. Narrow screens drop the signal columns.
- "Why it ranks here": the rank blend's parts, largest first, each as the signal's value and what it adds to the rank ("leverage 5.0, 100% of the most (+0.20)"); a part that adds nothing is left out, and a list sorted by one signal names that signal's value first, then the blend.
- Keyboard flow for triage: P passes the focus card (not while a field has the keys, not with a modifier); every action is a button in tab order. No other shortcuts: the actions take forms, and single keys there would fight typing.
- A card's and a row's actions are node detail's own where they exist: the answer editor, the snooze editor, the skip form (now exported), so a draft started on a card is the one the panel shows. Done on a deliverable that requires an artifact and has none opens an address field and sends the link and the completion as one patch. Assign owner sets the owner participation to the chosen entity explicitly (E2), the one write D2 names.
- Bulk actions: start, done (complete, or reach for a milestone), skip with one reason, assign owner, snooze until a date or a node, and unsnooze (B6). A selected node whose kind or state cannot take the action stops it before anything is sent, named; guards stay the engine's, so a guard failure rejects the one patch whole. A rejection now names the node each violation is on (`detail/Rejected.tsx`), since one patch can span several.
- The list's selection outlives paging, and a bulk action covers every node selected on any page (the bar counts those on other pages). Triage and the walkthrough with no card say whether filters hide what can be acted on; the walkthrough's diagnostic of what would unblock decisions is kept for when no one can make any.
- Pass is kept per tab in session storage, per journey, across both modes, with "Start a new pass" to reset it; the card count reads how many of the current cards have been passed.
- A title opens the node's detail on the canvas at the canvas's defaults: the acting screens' queries mean other things there (`in` is the list's group filter and the canvas's drill-in).
- The canvas's stalled surface (5.2) stays as it is; the acting screens' stalled panel adds D5's actions (unsnooze, confirm an auto-reach milestone reached now).
- Earlier work changed: the canvas page shows the journey's screens; node detail's skip form is exported; rejections name their nodes. The walkthrough's browser tests start their own journeys on the shared fixture server through the API (the creation screen is 5.5's), so no server-host test may count its journeys.
- Passing checks: `mise run check` (every rung), and `briefs/proof/5.3/prove.sh`.
- Planted bug: a bulk action sent as one patch per node (`acting/acts.ts`, `runBulk`, the bulk bar's one way to send), caught by C9's one-patch unit test: `FAIL src/acting/acts.test.ts > C9: bulk actions > sends the whole action as one patch`. The browser test of a rejected bulk completion fails on the same plant (the other node's patch lands).
