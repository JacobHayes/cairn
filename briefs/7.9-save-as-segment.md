## Goal

Let someone who built a good sub-process inside one route or journey lift it out as a segment. Saving drafts a proposal for a new segment the way save as route drafts a route: the selection keeps its keys, one top-most node becomes the root (several go under a new group root), and nothing that reaches outside the selection is carried; each cut is listed with "add it to the selection" as its remedy.

## Governing

- PRD: B15, B8 (the review it reuses), A21 (the segment rules the draft must meet), C14 and C19 (save as segment from a selection), I2, I6, J1, J3.
- ARCHITECTURE: Engine > Save-as-route and segments; Model (Proposal).
- DESIGN: Components (Multi-select).
- Decisions: `2026-10-09-a-segment-has-one-root-and-is-wired-in-through-it.md`.

## Scope

In:

- `save_as_segment(records, source, selection, segment, name)`: `create_route { kind: segment }`, `open_draft { save_as_segment { source } }`, the structure as ordinary mutations, and review items; the `saved_as_segment` event.
- The boundary as an informational `Boundary` review item per cut: a crossing edge dropped; an outside condition cleared; an outside date-rule source dropped (the rule cleared when none remain); an outside stage bound or fed milestone cleared; an outside answer placeholder replaced by the decision's title; an inherited participation from outside written onto the root; `final` and `default_owner` not carried. B8's participation mapping (no default owner) and exclusions apply, and no state is carried.
- Save as route drops a journey's insertions and lists them in one informational item.
- API `POST .../save-as-segment`; MCP `save_as_segment`; a line in `instructions/SKILL.md`.
- Screens: Save as segment acts on the existing selection (the inspector's actions for a journey, and a route draft's selection); a small form (name, id), then review in the new segment's frame with Dropped and Cleared items naming what to add to the selection. Applying opens the draft.

Out: saving into an existing segment as its next draft, and carrying insertions through save as route (PRD Later); the nesting test.

## Acceptance

- B15: a crossing edge is dropped and listed; an outside condition is cleared and listed; several top-most nodes get a group root.
- J3: the scenario "save-as-segment round trip" replays field by field.
- Playwright: select three nodes in a journey, save them as a segment, see the Dropped edge in review, apply, and publish the draft.
- A real bug its tests catch: a crossing edge kept, so the publish is rejected for a dangling reference.
