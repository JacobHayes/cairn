## Goal

Let someone who built a good sub-process inside one route or journey lift it out as a segment, and then, once it is published, make the original an insertion of it. Saving drafts a proposal for a new segment the way save as route drafts a route: the selection keeps its keys, one top-most node becomes the root (several go under a new group root), and nothing that reaches outside the selection is carried; each cut is listed with "add it to the selection" as its remedy. Linking is a second reviewed proposal to the source: the matched nodes become members under their own keys, so their differences from the version are simply the insertion's local edits.

## Scope

In:

- `save_as_segment(records, source, selection, segment, name)`: `create_route { kind: segment }`, `open_draft { save_as_segment { source } }`, the structure as ordinary mutations, and review items; the `saved_as_segment` event.
- The boundary as an informational `Boundary` review item per cut: a crossing edge dropped; an outside condition cleared; an outside date-rule source dropped (the rule cleared when none remain); an outside stage bound or fed milestone cleared; an outside answer placeholder replaced by the decision's title; an inherited participation from outside written onto the root; `final` and `default_owner` not carried. B8's participation mapping (no default owner) and exclusions apply, and no state is carried.
- `Mutation::LinkInsertion { insertion, segment }` and `insertion_linked`: members by the keys the version holds, identity role and kind maps, a wrapper group added when save created one (offered only when the top-most nodes share a parent); in a journey, matched nodes become `from_segment`, and a `from_route` one leaves the route's lineage, which review says.
- `merge` skips `from_segment` nodes, so a route upgrade never changes them.
- Save as route drops a journey's insertions and lists them in one informational item.
- API `POST .../save-as-segment` and `POST .../insertions/link`; MCP `save_as_segment` and `link_insertion`; a line in `instructions/SKILL.md`.
- Screens: the journey overflow menu's Save as segment enters Select mode, and on a route draft it is in the selection bar's overflow; a small form (name, id), then review in the new segment's frame with Dropped and Cleared items naming what to add to the selection. Applying opens the draft. After it is published, the source's header shows one dismissible line, "Make these 5 nodes an insertion of Security review v1?", whose `Review link` drafts the link.

Out: saving into an existing segment as its next draft, and carrying insertions through save as route (PRD Later); the nesting test.

## Acceptance

- B15: a crossing edge is dropped and listed; an outside condition is cleared and listed; several top-most nodes get a group root; after publish, linking makes the source an insertion of that version with its differences shown as edits; a linked `from_route` node is skipped by the next route upgrade.
- J3: the scenario "save-as-segment and link round trip" replays field by field.
- Playwright: select three nodes in a journey, save them as a segment, see the Dropped edge in review, apply, publish the draft, and link; Origin on a linked node then names the segment.
- Planted bug: keep a crossing edge, and show the publish rejected for a dangling reference.
