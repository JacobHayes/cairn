# 4.6: Web client and app shell

| | |
|---|---|
| Id | 4.6 |
| Crates or packages | `web/client` (hand-written wrapper), `web/app` (shell only) |
| Depends on | 4.5 |

## Goal

The React shell every screen brief builds on: one data layer over both hosts, the locally derived document, the shared write path with the H5 safe retry, and views that stay current across pages and tabs (H6).

## Governing

- PRD: H5, H6, D7 (the consequences notice), C15 (positions cached per revision); Non-functional: Small-team scale.
- ARCHITECTURE: Web UI (data flow, previews, version skew); Repository layout (`web/client`, `web/app`).
- PRACTICES: Code conventions (TypeScript); The validation ladder (rung 6, extended).

## Scope

In: the hand-written wrapper in `web/client` beside `web/client/generated/` (submit with the H5 safe retry using 4.5's wasm touched-set function; a subscription helper that tracks the held revision per domain and resubscribes after a drop); the app shell with routing, one data layer with server and in-browser implementations, `useJourney` returning the document derived in 4.5's worker, the shared write path through the wrapper with a consequences notice (D7), revision tracking per domain, refetch on newer ticks, on deployment ticks (refetching the deployment context), and at date rollover, the version-skew reload prompt, capabilities gating, and a small design-system skeleton; a host switch; Vitest and Playwright.

Out: every screen (phase 5); the binary (4.7).

## Acceptance

- The in-browser host loads each fixture and applies a patch; the server host runs against a test server assembled from 4.2's API over the memory store; a non-overlapping conflict retries transparently and an overlapping one surfaces.
- H6 in Playwright on the server host: an edit in one page appears in another; edits to different nodes both land; edits to one field surface a conflict; a later page shows the edit; a deployment tick refetches the deployment context and re-derives. (The index and owner cases land with their screens in 5.5; the run against the real binary lands in 4.7.)
- Version skew: a document from a newer engine stops local derive, preview, writes, and automatic retries and asks for a reload, keeping unsent edits.
- Planted bug: compare ticks against the revision fetched first instead of the one held now, and show the "later page shows the edit" test fail.
- Extends rung 6 with Vitest and Playwright.

## Decisions left to the implementer

- Router, query library, state management; design tokens.

## Decision log

Appended by the implementer.

- Router: React Router 8 (`react-router`), its `HashRouter` ([`decisions/2026-10-06-the-ui-routes-by-the-urls-hash-beside-the-apis-paths-on-one.md`](../decisions/2026-10-06-the-ui-routes-by-the-urls-hash-beside-the-apis-paths-on-one.md)). No query library: the data layer is a few stores (`web/app/src/data/`) behind `useSyncExternalStore`, because what to refetch is decided by the client wrapper's `Tracker` (H6), not by cache staleness, and the cache key is the derivation's (journey revision, deployment revision, today). No state library beyond React's.
- Design tokens: CSS custom properties in `web/app/src/ui/tokens.css`, light and dark following `prefers-color-scheme`; the components in `ui/kit.tsx` (button, field, badge, panel, capability `Gate`) are the skeleton screens compose.
- The client wrapper takes the engine's touched-set check as a function (`Overlaps`), so `@cairn/client` does not depend on `@cairn/wasm` (which depends on it for types). On the server host the page loads its own engine instance for it beside the derive worker's; the in-browser host already has one.
- One tick stream per tab over the union of what mounted views watch (`deployment` always, `journey:<id>` per shown journey, `journeys` while the index shows), reopened on a microtask when the union changes. Every view keeps its own `Tracker`, so a reopening's current revisions refetch only what moved. A deployment tick re-derives each held journey whose document carries an older deployment revision, and refetches the deployment context.
- Version skew is detected on the page before a document is posted to the worker (`engine_version` against the page engine's), and also from the worker's own refusal; either latches the tab. The skew tests simulate a newer server by rewriting `engine_version` in the document response (`page.route`), since every host in the tree runs one engine.
- Host choice: `?host=server` or `?host=browser`, else the server when `GET /capabilities` answers JSON at the page's origin; the header links to the other host.
- The server host's tests run against `crates/wasm/examples/fixture_server.rs`: the API over a memory store seeded as the in-browser root is, signed in by the dev provider (no token). An example, not a binary, so it adds only dev-dependencies (axum, cairn-auth, tokio).
- The journey page lists the nodes with their state and derived flags and a title editor, which the H6 and H5 acceptance cases need; it is the "temporary host screen listing a journey's nodes" 5.1 names, so 5.1 extends it rather than writing another.
- Edits outside `web/client` and `web/app`: `crates/wasm` (the fixture server example and its dev-dependencies), `mise-tasks/check/6` (Vitest suites, the fixture server build), `tsconfig.json` (`jsx`, `DOM.Iterable`, `web/*/proof`), root `package.json` (vitest), `ARCHITECTURE.md` (Web UI: addresses).
- Each Playwright run picks free ports for Vite and the fixture server in its config (inherited by its workers through the environment), so runs beside one another do not collide.
- Planted bug: `Tracker.fetched` keeping the revision fetched first, so ticks compare against it rather than the one held now; "a later page shows the edit" fails with `Expected: 2 Received: 4` document fetches (also two Vitest cases in `journeys.test.ts`). Restored, it passes.
- Checks: `mise run check:fast` after each change; `mise run check` at the end (see the report).
- Review round 1 (Opus), all six valid and fixed as new changes: a deployment tick heard during a journey's first fetch now re-derives it; rollover asks at every check until the host's today matches; an address that is not a journey id shows missing and is never watched (one malformed watch name made the server refuse the tab's whole stream), and a transport that throws on opening is retried as a closed stream; drafts are scoped by host and re-read when their key changes, and the journey page is keyed by its journey, so a draft never follows the screen to another journey with the same node keys; the title field is disabled while its save is in flight; the in-browser suite derives every fixture's journey. Each has a Vitest or Playwright regression case, shown failing with its fix removed.
