# 7.7: Segment screens

| | |
|---|---|
| Id | 7.7 |
| Crates or packages | `web/app` |
| Depends on | 7.6, 8.6, 8.11 |

## Goal

The screens that make segments usable without reading about them. Segments sit in the Library beside routes, a segment detail shows where each version is used and which uses are behind, and a segment draft is the route draft frame with one extra rule. Inserting takes three short steps in the inspector column (what, where, and who, the last only when the segment declares roles), previews the incoming root on the graph exactly as review will show it, and ends in the proposal review everyone already knows. On a member, Origin says which segment and version it came from and when a newer one exists. Upgrading an insertion (7.8) and saving a selection as a segment (7.9) add their entry points to these screens later.

## Governing

- PRD: C19, C14 (insert is reviewed as a proposal), C17 (the route screens these mirror), A12 (authoring on the canvas), B13, A21, C8 (Origin in node detail).
- ARCHITECTURE: Web UI (Screens, Previews).
- DESIGN: Approachable by default (one primary per step, folds over bands); Components (Status, Popover and menu).
- PRACTICES: Code conventions (TypeScript).

## Scope

In:

- Library: the `Routes` and `Segments` filter chips (both off shows all; add the type column if 8.6 shipped routes only); a segment row shows its name, the word "Segment", and one secondary fact ("Used in 6 places", or "2 of 6 behind" when any are), with its description on hover; `New` offers Route and Segment, which create the route with that kind and open its draft.
- Segment detail: the route detail layout with the header word "Segment", `Edit draft` or `Open draft` as the primary, and the overflow menu holding Export, Import into draft, and Retire; the versions table lists each version's insertions (host journey or route, the insertion's title, and an "Upgrade available" chip).
- Segment draft: the route draft frame with the header word "Segment" and no notices; when the one-root rule is broken, the draft card says "A segment has one top-level node. Put these 2 under a group." with `Wrap in a group`.
- The insert stepper, in the inspector column, one primary per step, from the journey's overflow menu (Insert segment), a container's overflow menu (Insert segment here, parent prefilled), and a draft canvas's Add menu (Insert segment):
  1. Choose a segment: a searchable list of published, unretired segments with name, one line of description, and size ("4 steps"); the latest version is chosen, with other versions folded.
  2. Place it: Under (a parent, or the top level), Name (defaults to the segment's title; shows the suffix when the id is taken), Starts after (host nodes the root will require), and Comes before (host nodes that will require the root). The incoming root and its wiring edges are drawn on the graph at their proposed place in review's Add style (success hairline, the Add tag, the segment and version in the band), not dashed and not ghosted.
  3. People, only when the segment declares roles or kinds: one row per segment role, defaulting to the graph's role with the same id, or New role. When the chosen role is already filled here, the row says so by name, and the stepper leaves the segment's filling decision out (`omit`), unless a segment condition reads it, when it defaults to New role; an `Ask separately` link switches to New role. Mismatched cardinalities are not offered.
  `Review` mints the insertion key, drafts one `insert_segment` proposal, and opens proposal review, where the incoming nodes are Add items outlined as one insertion with the segment and version, the wiring edges are Add edges, and added roles are listed. Closing review leaves the header's proposal chip.
- Origin: the inspector's folded Origin section reads "From segment Security review, version 2" when open, adds "inserted under Phase 2" on the root, and "Version 3 is available" when newer (text only). In Edit structure and on drafts, the insertion root's card foot names the segment and version. A member's overflow menu gains Show insertion (selects the root and fits it).

Out: the upgrade entry points and review title (7.8); Select mode's Save as segment and the link line (7.9); the Show origins lens; "Edited here" in Origin; the journey card's upgrade sentence counting insertions; the draft canvas's Add entry if 8.11 has no Add menu yet.

## Acceptance

- Playwright: from a journey container's Insert segment here, insert the fixture segment with Starts after set to a host node and `reviewer` mapped onto the journey's existing role; review shows the insertion's items, and applying shows the insertion and the host edge. Insert it again, and the name shows the `-2` suffix. The Library's Segments chip lists the segment with "Used in 2", its detail lists both under v1, and Origin on a member reads "From segment ..., version 1". Publish a v2 from the segment draft, and Origin reads "Version 2 is available".
- C19 and C14: the insertion's items appear and apply.
- Screenshots of stepper steps 1 to 3, review, the Library, segment detail, and Origin.
- Planted bug: drop the stepper's edges from the mutation, and show the edge assertion fail.
