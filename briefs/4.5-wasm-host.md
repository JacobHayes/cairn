# 4.5: Wasm host: engine package, derive worker, in-browser root

| | |
|---|---|
| Id | 4.5 |
| Crates or packages | `crates/wasm`, `web/wasm` |
| Depends on | 4.9 (the engine projections and preview it packages arrive with 2.6 and 2.7, and the full API with 4.9) |

## Goal

The browser as a first-class host: the engine and service compiled to wasm, deriving each domain document locally in a worker, and the in-browser root that runs the whole service over the memory store with no server, for UI development, demos, and end-to-end tests.

## Governing

- PRD: I1; Non-functional: Small-team scale.
- ARCHITECTURE: Web UI (data flow, version skew, in-browser host); Repository layout (`crates/wasm`, `web/*`); Storage > Backends (Memory); Generated artifacts.
- PRACTICES: Code conventions; The validation ladder (rungs 5 and 6).

## Scope

In: `crates/wasm` exports for every host (`derive`, `apply`, every projection, `explanations`, the touched-set function, import and export, `preview`) and the in-browser root (service, memory store seeded from the fixtures, in-process notifier, one local identity); `web/wasm/generated/` plus the hand-written loader and the derive worker; the engine-version check a host reads before deriving, previewing, or writing.

Out: the client wrapper and app shell (4.6); every screen (phase 5); persistence and cross-tab sync in the in-browser host (none by design).

## Acceptance

- Wasm `derive` of every fixture, in the worker, equals the server's derive byte for byte; every projection and `preview` agree likewise.
- The in-browser root loads each fixture, applies a patch, rejects a stale one, and notifies its subscribers.
- The engine-version check refuses a document from another engine version. The derive benchmark at the limits is repeated over the wasm32 module in Node and reported in the proof as a table.
- Planted bug: return the server's derive from a cache keyed without the deployment revision and show the byte-equality test fail after an entity edit.
- Adds rung 6 with these tests, which run in Node (Vitest) over the same wasm32 binary a browser runs: that is what catches drift only that target has (usize, floats, the stack). The worker in a real browser is covered by the app's in-browser smoke test (`web/app/e2e/browser.spec.ts`).

## Decisions left to the implementer

- The wasm packaging tool; how the worker and the main thread share the document.

## Decision log

Appended by the implementer.

- Packaging: the `wasm-bindgen` CLI stays (prebuilt, pinned in `mise.toml` at the crate's `=0.2.129`); wasm-pack would add a tool and an npm packaging step nothing uses. `mise run build:wasm` builds `crates/wasm` for `wasm32-unknown-unknown` with a `wasm` cargo profile (release, stripped, LTO, one codegen unit: 7.3 MB against 10.8 MB for plain release) and binds it with `--target web` into `web/wasm/dist/bindgen/`; `mise run gen` copies the JavaScript and declarations, with a header, into `web/wasm/generated/`. The bindings depend on whether the module is stripped (an unstripped one keeps its target features section, and wasm-bindgen then returns multiple values; a stripped one binds through the stack), not on LTO, so the faster `wasm-dev` profile the local check builds is stripped too and generates the same files (decisions/2026-10-08-the-check-builds-the-wasm-module-without-lto.md). No `wasm-opt`: it is not pinned and the size is not yet a problem.
- How the worker and the page share the document: the page keeps the document's text as fetched (it needs it for writes and previews anyway) and posts it to the worker once per revision; the worker derives it once and holds the derivation by journey until a newer one replaces it, answering projections, previews, and local applies as the module's JSON text, which the page parses (`web/wasm/src/protocol.ts`). A trap in the worker marks it aborted and every later call answers so.
- The in-browser root runs on the page's thread and synchronously: the memory store answers on the first poll, so `now_or_never` drives each service call, and a subscriber's ticks are taken after each write and again by a timer when the coalescing interval says wait. Its calls are text, so 4.6 can move it into a worker unchanged. It offers capabilities, the journey index, documents, the deployment, patches, and subscriptions; proposal and route operations join with the screens that need them (5.5, 5.7) as the same service calls.
- The root's answers mirror the API's wire types (`PatchAnswer`, `JourneyPage`, `Tick`) in `crates/wasm`, since `cairn-api` does not build for wasm; `tests/root.rs` parses each into the API's own type and writes it back to the same bytes.
- A local apply takes only the document journey's own patches, applies at the document's today, and answers the document after (the deployment after, when it creates entities) with D7 consequences derived as the service derives them (no viewer). A preview derives with no viewer, as the server's does, and takes the route versions an upgrade reads beside the proposal.
- An import mints new keys with the service's `PatchKeys`, now public, so a local import of a file is the draft the server's import of the same file under the same patch id opens.
- The engine version is `cairn_engine::engine_version()`, which `document` now uses too. A document's version is read before the rest of it, so a newer engine's document with fields this one does not know is refused as skew, not as unreadable.
- Depth limit in the wasm build (PRACTICES, No recursion): the date network's cost-test graph (`node_count_max` nodes, containment at the depth limit) is derived and projected in the browser's worker, including a trace from its deepest node, and compared byte for byte with the native build. The engine's own suites are not run under wasm (PRACTICES, Open questions).
- Rung 6 here is Vitest in Node over the module the build bound and the cases the server walk wrote (`web/wasm/src/agreement.test.ts`, `host.test.ts`); the derive worker's own script runs in the test's thread behind the `Worker` interface (`web/wasm/src/in-process.ts`), so the code under test is the browser's. It was first Chromium tests (Vite serving a harness page, `@playwright/test` pinning Chromium build 1243), moved to Node once the agreement cases had no need of a browser (the user's call). `@types/node` types the test files.
- The server walk reads as the root's local user, whose verified emails make each fixture's lead the viewer, and its patch notes, starts the first action or deliverable to do, and pins the first node it can make newly overdue (chosen with the engine directly, not the code under test), so every fixture's "mine" has work, every local apply causes D7 consequences, and every derive after the patch differs (review round 1; `the_walk_reads_as_a_viewer_and_its_patch_changes_every_fixture`).
- Edits outside `crates/wasm` and `web/wasm`: `crates/store/src/backend.rs` (an applied proposal's entity creates ride, [`decisions/2026-10-06-a-proposal-applied-to-a-journey-or-route-creates-entities.md`](../decisions/2026-10-06-a-proposal-applied-to-a-journey-or-route-creates-entities.md)); `crates/engine` (`engine_version`, and `edit::full_removal` gated behind `testing`, where alone it is used, so the module's build warns of nothing); `crates/service` (`Service::derived`, public `PatchKeys`); `crates/api` (`GET /journeys/{id}/derived` for it, as every service operation has an endpoint, with `openapi/` and `web/client/generated/` regenerated); `Cargo.toml` (the crate, `wasm-bindgen`, the `wasm` profile); `mise.toml` (the tool's comment); `mise-tasks/check/1` (the wasm build covers `cairn-wasm`), `mise-tasks/check/6`, `mise-tasks/build/wasm`, `mise-tasks/gen/wasm`; `tsconfig.json` (test and config files); `.github/workflows/check.yml` (installs Chromium); ARCHITECTURE's Web UI.
- Planted bug: the service's memo matching a derivation without its deployment revision; after the entity merge the agreement test fails, natively `vendor-evaluation after an entity merge: derive: answered 31212 bytes, the server 31050; first difference at byte 143` and in Chromium `✘ the browser host agrees with the server: vendor-evaluation after an entity merge` with five calls differing.
- Benchmark at the limits: the proof's table, which `briefs/proof/4.5/prove.sh` prints. On this host reading and deriving the 3.35 MB document takes about 0.4 s natively and 0.5 to 0.65 s in the worker timed from the page; writing every derived value (6.15 MB) takes about as long as natively (90 ms) and the top level up to half again as long (35 ms natively); the worker's linear memory peaks near 120 MiB.
- Checks: `mise run check:fast` exit 0 after each change of the stack; `mise run check` exit 0 with rungs 1 to 6, rung 6 running 14 browser tests; `briefs/proof/4.5/prove.sh` exit 0.
- Review round 1 (Opus): version skew and traps now latch per realm (`stop` in `web/wasm/src/types.ts`): every hosted call, the root's capabilities included, is refused with the first reason once a call trapped or saw another engine's document, or `Engine.accepts` answered false; the worker drops what it holds on either. The worker refuses a document older than the one it holds (`superseded`: an earlier revision, deployment revision, or day), and `DeriveWorker` rejects every pending and later request when the worker errors. A root subscriber's backwards or unrepresentable clock reading is `unreadable`, not a panic. Regression tests: four Playwright cases (skew, a trap, an older load, a failing worker), each shown failing with its fix removed; a root test of clock readings; a store conformance case on both backends.
- Planted bugs after review round 1: the memo without the deployment revision now fails as `vendor-evaluation after an entity merge: derive: answered 40499 bytes, the server 40475; first difference at byte 7159` (the walk merges a stakeholder, since merging the lead would change the viewer and miss the memo anyway); an empty viewer in `Derivation::projected` fails as `bake-off: project {"projection":"mine","kinds":[]}: answered 2 bytes, the server 45`; empty local consequences fail as `bake-off: apply the patch: answered 3438 bytes, the server 5839`.
