# 4.9: HTTP API completion: projections, proposals, route files

| | |
|---|---|
| Id | 4.9 |
| Crates or packages | `crates/api`, `openapi/` (generated), `web/client` |
| Depends on | 4.8, 4.2 |

## Goal

The endpoints for the operations 4.8 adds, on 4.2's router, auth layer, error bodies, limits, observability, and generated clients: every projection, proposals, route import and export, and the upgrade, save-as-route, and re-link flows.

## Governing

- PRD: I1, I3, A13, C14, I6 (the API half), H5 (proposal revisions).
- ARCHITECTURE: HTTP API (Resources, Bulk and import, Size budgets); Generated artifacts.
- PRACTICES: Errors, panics, and rejections; Explicit limits (request body, request duration, explanation entries per value in a response, snapshot top-N).

## Scope

In: `/snapshot` (I3), `/level`, `/trace/{key}`, `/decisions`, `/timeline`, `/summary`, `/next`, `/nodes/{key}` (C8 detail with capped, pageable explanations); proposals (`POST /{domain}/proposals` with client-generated ids, `GET` by id, `PATCH`, `POST .../preview`, `POST .../apply`, `POST .../discard`); route import and export (A13); save-as-route, re-link, and upgrade preview and apply, each a proposal underneath; regenerated OpenAPI and TypeScript types.

Out: the review screen (5.7); MCP tools over the same operations (4.3).

## Acceptance

- I1 (4.2's coverage test still holds with every new operation, its list of 4.8's operations awaiting endpoints emptied), I3 (paging and scoping), A13 (an export imported back as a new draft), C14, I6 (a proposal resubmitted by id is fetched, not duplicated; apply against a moved destination is stale with the intervening touched set).
- Planted bug: drop the explanation cap on node detail and show the size-budget test fail.

## Decisions left to the implementer

- URL spellings within ARCHITECTURE's shapes; the import body's media type.

## Decision log

Appended by the implementer.

- Planted bug: with `crates/engine/src/derive/project.rs` no longer cutting explanation lists to the response limit (`let cut = complete;`), `projections::node_detail_caps_its_explanations_and_the_rest_page` fails (`cut to the response limit`, `left: 103`, `right: 50`); restored, it passes (`briefs/proof/4.9/`).
- URL spellings: the projections under the journey, `GET /journeys/{id}/snapshot`, `/level`, `/trace/{key}`, `/decisions`, `/timeline`, `/summary`, `/next`, `/mine`, `/history`; the list (C9) at `GET /journeys/{id}/nodes`, one node at `/journeys/{id}/nodes/{key}`, and its explanation pages at `/journeys/{id}/nodes/{key}/explanations/{gravity|leverage}?cursor=`; proposals as [`decisions/2026-10-06-a-proposal-is-created-under-its-domain-and-addressed.md`](../decisions/2026-10-06-a-proposal-is-created-under-its-domain-and-addressed.md) says; upgrade, save as route, and re-link at `POST /journeys/{id}/upgrade`, `/save-as-route`, `/relink`; route files at `GET /routes/{id}/export?version=` (the draft when none) and `POST /routes/{id}/import`.
- Query parameters, declared once per endpoint as in 4.2: the snapshot `subtree`, `depth`, `cursor`, `revision`; the level `kind` (repeated; every kind when none, so a bare `GET .../level` is the whole canvas) and `container`; the next list `sort`, `mine`, `kind`, `within`, `for_viewer`; the list `flag`, `within`, `owner`, `state`, `kind`, `text`, `sort`, `cursor`, `revision`; explanation pages `cursor`, `revision`; mine `kind` (participation kinds); history `node`, `after`. A projection's page continues from its `next` cursor, which is a position in the order at one journey revision (review round 1): a cursor past the start needs the `revision` of the page it came from (400 without it), and once the journey has moved the page is refused 409 `page_moved` rather than continuing a reordered list with a repeat or a gap. The check is the API's, against the revision the page was derived from; the cursor itself stays the engine's position, so the browser, which derives locally, is unaffected.
- Every derived read answers `Projected<T>` (`revision`, `deployment_revision`, `today`, `value`), named `Projected<T's name>` in the document; mine's list is wrapped as `Mine { entries }` so its schema has a name. Node detail and history are the service's shapes given serde in `wire/projections.rs`. History of a journey that does not exist answers 404, as the service's history refuses it (4.8's review fixes).
- The import body is JSON (`{patch_id, file, note}`), the route file as the format's JSON (ARCHITECTURE, File format: JSON on the wire); its route must be the path's (`target_mismatch` otherwise). An export answers the `RouteFile` as JSON; a client wanting YAML converts it.
- Every write (proposal writes, applies, drafts, imports) runs on its own task like a domain patch (`handlers::committed`), logs its patch id and outcome, and counts in `cairn_api_patches_total` with the outcomes `saved`, `already_saved`, `existing`, `not_drafted` (only a `cannot_draft` refusal), and `not_found` (a proposal, journey, or version the write names, including the proposal lookup before an edit, discard, or apply) beside 4.2's.
- `cairn-engine` is now a dependency of `cairn-api` rather than a dev-dependency: the API maps `DraftError` (carried by the service's `ProposeError`) to not found or `cannot_draft`. The API still calls only the service.
- An upgrade to the version a journey already follows is drafted as an empty proposal (2.7's engine allows it); only an older version is `cannot_draft`.
- `AWAITING_ENDPOINTS` is gone from `tests/openapi.rs`: every service operation is in `offered_by`. The coverage loop also sends each endpoint signed in and refuses a 405, so an endpoint served with the wrong method fails it (review round 1; checked by serving preview as GET). The conformance test grew proposal and bulk cases, including route and deployment proposals and a preview with consequences, each answer validated against the document at its status. A resubmitted apply is answered from its receipt (`already_applied`), as 4.8's review fixes made it.
- Test support: `World::vendor_quietly` and `World::quiet` keep set-up out of the proof's transcripts (with a note in its place); 4.2's tests keep `vendor_after` and their transcripts are unchanged.
- Edits outside the brief's paths: ARCHITECTURE's HTTP API line on proposals and two files in `decisions/` ([`decisions/2026-10-06-a-proposal-is-created-under-its-domain-and-addressed.md`](../decisions/2026-10-06-a-proposal-is-created-under-its-domain-and-addressed.md), [`decisions/2026-10-06-a-request-cairn-cannot-draft-answers-422-with-a-problem.md`](../decisions/2026-10-06-a-request-cairn-cannot-draft-answers-422-with-a-problem.md)).
