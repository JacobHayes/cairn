# Proof for brief 4.8: Service completion: priority, projections, proposals, route files

A host can now ask the service for every derived view of a journey, run proposals from
draft to review to apply, upgrade a journey to a new route version through a proposal, and
move routes in and out as files. The memory store and a Turso file answered every step the
same way.

## Before and after

The vendor evaluation's next list for its lead once kickoff is reached:

| Position | Node | Rank | Gravity | Leverage |
|---|---|---|---|---|
| 1 | Environment access | 0.450 | 1.000 | 1.000 |
| 2 | Decision meeting | 0.185 | 0.741 | 0.000 |
| 3 | Test workload | 0.019 | 0.074 | 0.000 |

An agent proposes a charter that kickoff, already reached, must wait on:

- Created again by id after a lost response, it answers with the same proposal.
- An edit or an apply against an older proposal revision is stale.
- The preview shows what it would cause: kickoff stale, the charter 25 days short and
  overdue. The apply causes exactly that, and records the reviewer as confirming it.

The journey upgraded to route version 2 through a proposal:

| Aspect | Before | After |
|---|---|---|
| Lineage | version 1 | version 2 |
| Access title (in conflict, route's side chosen) | Access to the test environment | Environment and data access |
| Sign off the recommendation | absent | added |
| Test workload | from the route | orphaned, kept |
| Findings estimate (local edit) | 4 | 4, kept |

The agent's apply is refused until the conflict is resolved; once it is, the apply records
the agent's user as confirming it. Version 2 exported, its node
keys stripped and imported back, opens a new draft whose graph equals version 2, every node
matched by path.
