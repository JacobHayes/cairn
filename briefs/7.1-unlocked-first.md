# 7.1: Unlocked nodes first in a pass

| | |
|---|---|
| Id | 7.1 |
| Crates or packages | `web/app` |
| Depends on | 5.3 |

## Goal

Make a triage pass, and the decision walkthrough in particular, follow a line of work before moving on: after any action on a card, the nodes that action brought onto the acting frontier come next, ahead of the cards already waiting, each labeled with the card that unlocked it. Answering one decision then leads straight to the decisions it opened, the way a flowchart walks its branches, while the shared rank stays what every other surface shows.

## Governing

- PRD: C11 (the ordering after an action), C10 and Priority (the shared rank the pass leaves alone), C5 (rank badges unchanged).
- ARCHITECTURE: Web UI (Screens; a pass is client state).
- PRACTICES: Code conventions (TypeScript).

## Scope

In: the pass order in `acting/pass.ts` and the triage screen: what one action unlocked is the set of keys on the acting frontier after it that were not on it before it, within the same pass; those come next in rank order among themselves, ahead of the waiting cards, and a later action's unlocks go ahead of an earlier action's. Passed cards still go to the back. Each unlocked card carries an "unlocked by" label naming the card whose action brought it on. The label and order survive a refetch of the journey within the pass, and a new pass starts from plain rank order.

Out: the shared rank and its badges (Priority, C5), the next list's order (C10), and the agent snapshot (I3): none of them change.

## Acceptance

- Behavior by id: C11 (order after an action; label; pass emits no event), C10 (next list order unchanged by a pass).
- Playwright over a route-file variant of the vendor evaluation that adds a follow-up decision relevant only when a partner runs the testing (no fixture yet has a decision whose relevance reads another decision): in the walkthrough, answering the partner decision puts the follow-up next, labeled with it, ahead of up-front decisions that outrank it; passing an unlocked card moves it to the back; starting a new pass returns to rank order. In triage, completing the test plan's last child action brings the plan next, labeled. The next list in another tab shows the same order before and after.
- Unit tests in `acting/pass.test.ts` for nested unlocks (an unlocked card whose action unlocks more) and for an unlocked card that leaves the frontier before it is reached.
- Planted bug: order unlocked cards by rank among all waiting cards, and show the walkthrough test fail.

## Decisions left to the implementer

- Wording and placement of the "unlocked by" label; whether it fades once the card is acted on or passed.
