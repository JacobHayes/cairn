# 4.4: Assistant

| | |
|---|---|
| Id | 4.4 |
| Crates or packages | `crates/assistant`; its endpoints mounted in `crates/api` |
| Depends on | 4.3 |

## Goal

The optional in-app assistant: a vendor-neutral provider trait with three implementations, a server-side tool loop over 4.3's in-process tool set, proposals for structural changes and for any direct write over the node limit, and attribution of every mutation.

## Governing

- PRD: I5, I7, H2, A12, B10 (assisted per-member breakdown); Success criteria (route draft and ad-hoc structuring in ten minutes).
- ARCHITECTURE: Assistant; Service layer and composition (an optional subsystem mounts itself).
- PRACTICES: Explicit limits (direct-write node limit, tool-loop iterations, provider call, turn duration, turns in flight); Simulation (`buggify!` at the provider call).

## Scope

In: the provider trait in Cairn's own types; Anthropic Messages (API key), OpenAI (API key), and a generic OpenAI-compatible endpoint; a scripted provider for tests; the turn loop; the one write wrapper every assistant tool call passes through (structural mutations and patches touching more than the limit become one proposal; `apply_proposal` is refused, since applying is the user's click); `POST /journeys/{id}/assistant` and `POST /routes/{id}/draft/assistant` mounted in the API; conversations per target per user.

Out: the panel (5.8); streaming replies.

## Acceptance

- A12 (a route drafted in conversation arrives as a proposal on the draft), I5 (each clause), I7, H2, B10 (per-member breakdown writes explicit participations); each provider round-trips a tool call against a recorded fixture of its wire format.
- Policy by destination: a weight change on a route draft is a proposal; the same change as a journey override applies directly. A direct write reports its consequences.
- Planted bug: let a structural mutation through the wrapper on one tool and show its policy test fail; the policy tests iterate every write tool, so a new unwrapped tool fails too.

## Decisions left to the implementer

- Context construction from the snapshot; conversation retention.

## Decision log

Appended by the implementer.

- Calls that shape the design are in `decisions/`: the wrapper's policy and what "touched" counts; the Responses API and the fixtures written from references; conversations and context; where the endpoints are served; the store fix for an applied proposal's entity creates.
- Context construction: each turn reads its target as the user (journey: `get_snapshot`; route draft: `get_route`, or a `not_found` note when the route or its draft does not exist yet) and puts it in the system prompt after the shipped guide, every workflow, and the write policy. Retention: the newest 200 messages per conversation, dialogue and write reports only.
- The assistant's agent id is `ag_assistant`, as the bake-off fixture already names it. Agent tokens are minted with random ids, so none collides.
- A write drafted as a proposal is filed as `pr_` and 24 hex digits of the SHA-256 of its patch id, under the same patch id; its title is the first line of the write's note, else "N change(s) from TOOL, drafted by the assistant".
- The model is offered every tool but `apply_proposal` and `import_route`; the wrapper refuses those two anyway, should a model call them.
- Tool results go to the model as the tool's JSON output, or its `ToolError` as JSON with `is_error`.
- `ScriptedProvider` plays `Step::Reply`, `Fail`, `Hang` (never answers), and `Slow(duration, reply)`, and records every exchange; it is public so the API's tests and the proof use it.
- The protocol modules are pure (`request`, `reply`) beside one `HttpProvider` that posts; the credential is a `Credential` whose `Debug` hides it, sent only as a header, and a transport error drops its URL.
- `cairn-assistant` joins the crates rung 1 holds to `-D clippy::panic`, as the API and MCP are.
- Edits outside `crates/assistant`, each needed by this brief: `crates/mcp` (`ToolSet::drafted_patch`, and `write` going through it); `crates/store` (the shape fix and its conformance case); `crates/api` (the endpoints, handlers, wire types, OpenAPI operations, `router_with_assistant`, test support, `tests/assistant.rs`, and `tests/http.rs`, whose every-endpoint auth check now runs on a root with the assistant); regenerated `openapi/cairn.json` and `web/client/generated/api.ts`; `mise-tasks/check/1` (scoped lints); workspace `Cargo.toml` (the crate and reqwest); ARCHITECTURE (the Assistant section and the crate graph: `mcp --> assistant --> api`).
- Planted bug: `decide` letting `resolve_date_conflict` apply directly; `every_write_tool_is_decided_by_mutation_kind_and_destination` failed with `resolve_date_conflict: Ok(Direct), expected Propose(Structural)` (and the run test with a stale write landing where a proposal should); restored, both pass.
- Checks: `mise run check:fast` exit 0 for the stack; `briefs/proof/4.4/prove.sh` exit 0; `mise run check` in the report.
- Review round 1 (Opus), fixed as new changes:
  - P1: the ten-node limit now holds per turn. A ledger keeps the nodes the turn's direct writes touched, and the overflow goes into one proposal per destination. Replies are capped at 32 calls, and the deadline is checked before each call.
  - P2: a removed note counts the node it is on.
  - P3s:
    - a skip or reopen counts its subtree; the role-fill reading is recorded;
    - one turn per conversation;
    - dialogue byte budget and response cap;
    - no conversation stored for a missing route;
    - a discard is reported as one.
  - Regression tests: `turns.rs` (split calls across replies with injected journey text, overflow as one proposal, per-reply cap, deadline before a call, busy conversation, missing route and discard), `policy.rs` (note removals and container skips), `protocols.rs` (response cap), and `conversation.rs` (dialogue budget).
  - Ported in spirit from the reviewer's scratch `review.rs`: the split-call case now ends with ten applied and one proposal, the twelve-note removal is a proposal, and the container skip counts its subtree.
- Review round 2 (gpt-6.1-sol, medium): one P2, valid. A stalled store under a tool call, the context read, or the conversation load or save was not held to the turn limit. Fixed:
  - each tool call runs on its own task under the work deadline;
  - the reads are held to it as well;
  - the save is held to the turn limit, with a 5 s reserve.
  - Regression test: `a_stalled_commit_cannot_hold_a_turn_past_its_limit` (the memory store's commit pause hook).
