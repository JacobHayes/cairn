# 4.7: The binary

| | |
|---|---|
| Id | 4.7 |
| Crates or packages | `crates/cairn` |
| Depends on | 4.4, 4.6 |

## Goal

`cairn serve`: configuration from a file plus environment overrides with no defaults for deployment-specific values, the composition root, the embedded web build, one port for API, MCP, assistant, SSE, and UI, and structured logs and metrics.

## Governing

- PRD: Non-functional: Deployable, Observable; A9 (timezone is configuration); Priority (rank constants).
- ARCHITECTURE: Service layer and composition; Build, run, deploy; Observability; Auth.
- PRACTICES: Scope and dependencies (the configuration surface); Errors, panics, and rejections (the panic policy).

## Scope

In: `cairn serve`, `migrate`, `config check`, `version`; the configuration schema with exactly PRACTICES' surface; the root (Turso, the in-process notifier with a tokio timer, auth providers, the optional assistant); `rust-embed` of the web build, built by a mise task before `cargo build` and never checked in; JSON tracing and `/metrics`; the TCP listener set with `TCP_USER_TIMEOUT` equal to `SSE_WRITE_STALL` (and keepalive), so a peer that stops taking writes is disconnected at the socket ([`decisions/2026-10-06-where-the-sse-write-stall-is-enforced.md`](../decisions/2026-10-06-where-the-sse-write-stall-is-enforced.md)); a `Host` allowlist in front of the whole router (API, MCP, auth routes, UI) built from the public URL's authority, plus loopback names when the listener is loopback-bound, so a page rebound by DNS to the server's address cannot reach the providers that trust the peer (the dev user, Tailscale direct) ([`decisions/2026-10-06-dns-rebinding-protection-is-a-host-allowlist-in-front.md`](../decisions/2026-10-06-dns-rebinding-protection-is-a-host-allowlist-in-front.md)); `mise run serve`.

Out: containers, supervision, TLS termination (a proxy's job; noted in the README).

## Acceptance

- A fresh machine with the binary and a config file serves UI and API on one port with its database file; a missing timezone or public URL fails at startup naming it; rank constants are validated at startup (non-negative, blend weights summing to one, discount within 0 to 1); the assistant is absent from capabilities when unconfigured.
- A smoke test starts the binary, fetches capabilities and a fixture journey's document and snapshot, and stops.
- 4.6's H6 Playwright suite passes with the server host against the real binary.
- An SSE client that stops reading, with the stream still ticking, loses its subscriber slot within the write stall plus one coalescing interval.
- A request whose `Host` is not the public URL's authority (or, on a loopback-bound listener, a loopback name) is refused before the auth layer, on the API, `/mcp`, and the UI alike; the configured host is served.
- Planted bug: default the timezone silently and show the startup test fail.

## Decisions left to the implementer

- Configuration format (TOML is expected), environment variable naming, CLI crate.

## Decision log

Appended by the implementer.

- Configuration format TOML (`toml`), CLI `clap` with derive: `cairn serve|migrate|version` and `cairn config check`, each but `version` taking `--config FILE` or `CAIRN_CONFIG`. The file's shape, the override variables, and what defaults are in [`decisions/2026-10-07-the-configuration-is-one-toml-file-with-a-fixed-set.md`](../decisions/2026-10-07-the-configuration-is-one-toml-file-with-a-fixed-set.md). A relative database path in the file is relative to the file's directory; one from `CAIRN_DATABASE` to the working directory, as a shell would read it.
- `config check` builds every auth provider over a throwaway memory store, so a provider that refuses its listener or URL (dev off loopback, Tailscale proxy on a public address, an OIDC issuer over http) fails the check as it would fail `serve`, without opening the database.
- `migrate` is the store's own open (create if absent, MVCC, pending migrations in one transaction); `serve` opens the same way, so a deployment never has to run `migrate` first.
- The listener is TCP only; a unix socket (which the auth crate's `Listener::Unix` allows) has no `TCP_USER_TIMEOUT` and no deployment asks for it yet.
- `crates/cairn` is a library and a thin `main.rs`, so tests assemble the real composition root (`root::app`) in process over a memory store, a stand-in web build, and their own notifier.
- The web build goes to `web/app/dist/build/` (Vite `build.outDir`), apart from the browser tests' reports in `web/app/dist/`, so a report is never embedded. `rust-embed` embeds it in every build (`debug-embed`, so a debug build never reads another checkout's folder through a compile restored from the build cache); `build.rs` reruns when the directory changes and hands the compile a digest of it, so a binary built before the web build is rebuilt after it, under the build cache too. `serve` refuses to start without `index.html`. Hashed bundles are served `immutable`, the page `no-cache`.
- Logs: tracing-subscriber's JSON format on standard error at info and above, each line with its span's fields (request id, endpoint); no level knob (PRACTICES: no configuration by default). Stopping: SIGINT or SIGTERM stops accepting, waits up to the request duration (5 s) for requests in flight, and exits 0; SSE streams, which never end by themselves, are dropped then.
- The Prometheus exporter's histogram upkeep runs every heartbeat interval (10 s), a borrowed limit like keepalive's.
- `mise run build` (release binary with the web build), `mise run build:web`, and `mise run serve` (debug binary over `cairn.dev.toml`: loopback, UTC, the dev provider, database under `.cairn/`).
- Tests: `src/config` (rung 2) for every required value, override, provider kind, and rank breach; `tests/server.rs` `mod in_process` (rung 4) for the Host allowlist on every surface, capabilities with and without the assistant, the UI, metrics, startup refusals, and the socket-level write stall; `tests/binary.rs` `mod commands` (rung 2) runs the binary for startup failures, environment overrides, `migrate`, and `version`, and `mod binary` (rung 6, after the web build) is the smoke test and a closed log stream. Rung 6 also runs 4.6's server-host Playwright suite against the binary (project `binary`, over `scripts/e2e-binary`: a fresh directory, the fixtures seeded by `examples/seed_fixtures.rs`, `cairn serve` on a free port or `CAIRN_E2E_PORT`).
- Found while testing: a server whose standard error was closed aborted on its next log line (tracing-subscriber `eprintln!`s its own write errors, and `eprintln!` panics); internal error reports are off and a regression test closes the pipe ([`decisions/2026-10-07-the-binary-aborts-on-a-panic-outside-an-engine-call.md`](../decisions/2026-10-07-the-binary-aborts-on-a-panic-outside-an-engine-call.md)).
- Edits outside `crates/cairn`: `crates/service` (derive timing, the engine-call flag), `crates/store-turso` (commit timing), `web/app` (Vite's build directory, the `binary` Playwright project), `mise-tasks/check/2`, `4`, `6`, `mise-tasks/build`, `mise-tasks/serve`, `scripts/e2e-binary`, `README.md` (Run), `ARCHITECTURE.md` (Build, run, deploy: the listener).
- Planted bug: the time zone defaulted to UTC when missing (`file.timezone.or(Some("UTC"))` in `config/values.rs`); `a_missing_deployment_value_fails_naming_it` fails with `left: [] right: ["timezone"]`. Restored, it passes. Also shown: with the listener's `set_user_timeout` commented out, the write stall test fails with `freed after 44.938392382s, past the stall and one interval` (the slot then waits for the send buffer to fill and the API's own stall).
- Checks: `mise run check:fast` after each change; `mise run check` at the end (see the report).
- Review round 1 (gpt-6.1-sol, high), all four valid and fixed in one change on top: `/metrics` and the UI bypassed the in-flight limit (now beside the API under its limits through a new `cairn_api::router_beside`; a test fills the API with unfinished requests and sees 503 on every surface, 200 on `/metrics` before the fix); two built-in OAuth servers passed `config check` and then aborted `serve` on their shared well-known paths (now a configuration problem); a non-Unicode variable anywhere in the environment panicked startup (`vars_os`, and a non-Unicode `CAIRN_` variable is a problem); an IPv4-mapped loopback listener lost the loopback names (canonicalized first).
- From 6.2: the store is opened once, and a failed open exits nonzero rather than retrying ([`decisions/2026-10-07-a-database-that-does-not-open-stops-the-binary-it-never.md`](../decisions/2026-10-07-a-database-that-does-not-open-stops-the-binary-it-never.md)); `commands::a_database_that_does_not_open_stops_the_process` covers `serve` and `migrate`.
- Review round 2 (gpt-6.1-sol, high), all three valid and fixed in one change: a request with an invented method made a new metric series per method (P1; the API's request metrics now label any method outside HTTP's own as `other`); `sign_in_with` accepted a provider with no sign-in page (now only an OIDC provider); the binary's tests and `scripts/e2e-binary` passed the caller's `CAIRN_` overrides and secrets to the binary (now none reach it). Round 3 follows the P1.
- Review round 3 (gpt-6.1-sol, high): one valid P2, fixed: the proof script passed the caller's `CAIRN_` variables to the binary, so an exported `CAIRN_DATABASE` opened another database; it now clears them all first. Rounds end at three.
