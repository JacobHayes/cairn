# 2.1: Engine core

| | |
|---|---|
| Id | 2.1 |
| Crates or packages | `crates/engine` (model, validate, apply, transition, event, replay) |
| Depends on | 1.2 |

## Goal

The in-memory graph model and the one write path. After this brief a host can build a graph from 1.2's documents, apply a patch and get either a change set with one event per mutation and the next revision or a complete rejection, and rebuild any graph from its events. Every structural invariant holds on every accepted graph, every state machine allows exactly its table's transitions, and fixtures load through the model. The validation stages that need derived state arrive with 2.2, 2.3, and 2.4.

## Governing

- PRD: Core concepts; Identity and references; Containment (the tree); A2, A3, A4, A6, A7, A11 (publish as copy), A15 to A18, B1 to B5, B10, B11, D1, D1a (the stored side), D4 (`has_artifact`, `broken_down`, bypass recording), E3, E6, G1, G2, Invariants (graph and journey, except the date line), J1 to J3.
- ARCHITECTURE: Engine > Model; Write path: apply; Testing the engine.
- PRACTICES: Rules; Errors, panics, and rejections; Testing > Engine.

## Scope

In: `Graph` and `Deployment`; `apply` with the validation pipeline as an ordered stage list that later briefs extend, and an `Applied` only the pipeline can build; the change set by diffing base and candidate; the A18 removal cascade; the per-kind state machines, with reopen clearing what the D1 tables say, a container skip as one event, and a transition on a snoozed node clearing its snooze in the same event; role fills routed through their filling decision (E3); same-patch entity create (E6); building a graph from a file document with no base version (supplied keys kept, missing ones minted through a host-supplied allocator), so fixtures load; retired keys kept per graph; publish; events and `replay`; the scenario harness (one J3 matrix entry per scenario naming its PRD id and owning brief, checking expected state as well as replay equality); `testing::{arb_graph, arb_ops, Op}`; every structural invariant check and the cycle check over explicit and containment edges.

Out: everything derived (2.2 to 2.6); import against a base version, export, and merge documents (2.7); storage.

## Acceptance

- Behavior by id: A2, A3, A15 (three independent violations report three), A16, A17 (all or nothing; a base revision mismatch is a rejection), A18 (a removal leaving a dangling condition is rejected unless the patch fixes it; a removal whose subtree or edges gained a node or edge it does not name is rejected, including a child moved in, and one whose node gained a note or participation since; a removed key re-added as a new node is rejected), B1, B4 (markers set and reset; tombstone on removal), B5, B10, B11 (archived accepts only un-archive or delete), D1 (every row of every table), D1a (one event; reopen restores), D4 (a bypass records the failures it bypassed), E3, E6, G2, J1 to J3.
- Properties: apply then replay equals apply; a rejected patch leaves the graph unchanged; event count equals mutation count.
- Planted bug: skip the tombstone write on removal, in state and event both, and show the B4 scenario fail on its expected-state check.
- Fixtures: all parse into `Graph`; the vendor evaluation scenario runs through apply and replay.
