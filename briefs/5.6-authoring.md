# 5.6: Authoring: structure editing on the canvas and in node detail

| | |
|---|---|
| Id | 5.6 |
| Crates or packages | `web/app` |
| Depends on | 5.5 |

## Goal

Everything a person does by hand to change a graph's structure, for a route draft and a journey alike: add, edit, move, and remove nodes; draw and delete edges; roles, participation kinds, and `default_owner`; conditions, date rules, stage bounds, weights, estimates, flags, decision prompts and choices, and resources; breakdown by hand; local edits and reset; the removal cascade. Every edit is previewed with the wasm engine and sent through 4.6's write path, with rejections shown at the field.

## Governing

- PRD: A1, A1a, A2 to A8, A10, A12 (the by-hand path), A15, A16, A18, B4, B10, Identity and references, Invariants; Non-functional: Config-first.
- ARCHITECTURE: Web UI (Previews, Canvas); Engine > Conditions.
- PRACTICES: Explicit limits (each editor enforces its limits before sending).

## Scope

In: edit mode on 5.2's canvas (a toggle on a journey, always on for a draft); `NodeForm`, `ConditionEditor`, `DateRuleEditor`, `StageBoundsEditor`, `RolesAndKindsPanel`, `ResourceEditor` (placeholders picked, stored as key references), `CascadeDialog`, exported for 5.7; local-edit markers with reset and tombstones with restore; breakdown by hand and mark atomic.

Out: date pins and conflict resolution (5.1), proposal review (5.7), the assistant (5.8).

## Acceptance

- Behavior by id: A1a (a kind's form offers exactly its fields), A3 (an ancestor or descendant edge is refused with the reason), A5 (every operator reachable; a type mismatch cannot be entered), A8, A12 (a route authored by hand exports to a file that re-imports to the same graph), A15 (three violations at three fields), A18, B4, B10, Identity and references (renaming a node referenced by a condition leaves it intact).
- Playwright on the in-browser host: author a small route from an empty draft (two decisions, a stage, three deliverables with a condition and a date rule, a milestone, a role with a filling decision), publish, export; on a fixture journey, add a local node, edit and reset a route-copied title, remove a node with a dangling condition and resolve the cascade.
- Planted bug: send a removal without its cascade and show the A18 test fail.

## Decisions left to the implementer

- Palette or context menu, inline or panel forms, drag affordances; whether journey edit mode is a toggle or its own path.

## Decision log

Appended by the implementer.

- Journey edit mode is a toggle on the canvas, kept in the address (`edit=on`) with the rest of what the canvas shows; a route's draft is always in edit mode, and a published version is read only with an offer to open a draft. A draft node's structure opens at `/routes/<id>/nodes/<key>`, beside the canvas as a journey node's detail does.
- A palette, not a context menu: kind, title, and container (the one drilled into by default, kept between adds). A new decision starts as a yes-or-no question whose prompt is its title. Forms are panel forms beside the canvas; nothing is dragged (layout stays automatic, C15). A requirement is drawn by "Draw it on the canvas" and then picking the required node's card; Escape stops drawing.
- A node form saves one patch of one-field mutations; an answer-type change is a `replace_node`, the only way the engine takes one. The draft survives a reload and is sent against the revision its author started from (H5). What it would send is previewed by a local apply in the derive worker as the author types, so violations show at their fields before Save; Save previews again and sends nothing the engine refuses.
- A route draft's local apply is new in `crates/wasm` (`apply_route`), through the derive worker beside the journey's; `Deriver` gains both. A route has no state, so its preview has no consequences.
- Where a violation shows: the engine's `at.field`, else the field of the mutation it rejected, else its code's field (a duplicate id at `id`, a second final milestone at `final`, an edge to an ancestor at the requirements); a violation of another node, or of none, is listed with the form.
- The stage-bounds picker offers milestones inside the stage too, after the others and marked, so the engine's F4 rule shows at the field rather than the option silently missing. Fills-role offers only roles of the decision's cardinality and the condition editor only the comparisons a decision's answer type takes: those are type mismatches, which cannot be entered (A5).
- A removal's cascade rewrites rather than removes: a condition drops the clauses naming a removed decision (an emptied combinator goes with them, an emptied condition is cleared), a date rule drops the removed source (cleared when none is left), a stage bound and `feeds_milestone` are cleared, a snooze on a removed node is lifted, and a message draft drops the placeholders naming it. Removing a role or kind clears its participations, `fills_role`, the default owner, and draft placeholders first.
- Rejections no field owns, and stale ones (H5), show under the form or the control that sent them, with "keep my edit on the current version".
- Saved notices pile up over the bottom of the node panel (4.6's notices never dismiss themselves); the browser tests dismiss them. Left as is: changing the shell's notices is outside this brief.
- The canvas refits when authoring adds or removes a card (`canvas/refit.ts`); outside edit mode a revision still keeps the viewport (5.2).
- Earlier work changed: the canvas view gains `edit` (`canvas/settings.ts`); `NodeDetailPanel` takes an `extra` section under its header; `JourneyCanvas` takes `onPick`; the route canvas opens a draft's node; the route index gains "start a route with an empty draft"; rung 6 builds the module before its Vitest suites (`decisions/2026-10-07-authorings-unit-tests-check-the-editors-rules-against.md`).
- Tombstone restore and reset to route: `decisions/2026-10-07-restoring-a-tombstone-adds-a-local-copy-under-fresh-keys.md`.
- Planted bug: a removal sent without its cascade (`removalMutations` sends only the `remove_node`); A18's cascade tests failed: `FAIL src/authoring/cascade.test.ts > planRemoval (A18) > removing a decision a condition names is accepted with its cascade AssertionError: expected { accepted: false, …(2) } to deeply equal { accepted: true }`.
- Review fixes: a node form's draft keeps only the fields its author changed; resource, role, and kind edits, breakdown pieces, the palette, and the new-route form are kept as drafts across reloads and sent against the revision they were opened at, with "keep my edit on the current version" after a conflict; the structure panel is keyed by node so each node's drafts stay its own. A node form draft in the shape before these fixes is not migrated: that shape never shipped.
