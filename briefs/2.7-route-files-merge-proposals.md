# 2.7: Route files, upgrade, save-as-route, re-link, proposal documents

| | |
|---|---|
| Id | 2.7 |
| Crates or packages | `crates/engine` (modules `format`, `upgrade`, `proposal`) |
| Depends on | 2.6 (previews show the resulting frontier, which needs every pass) |

## Goal

The route file format end to end (import against a base version by path, deterministic export), and the engine functions that turn two graphs into a reviewable proposal (upgrade by three-way merge over keys and local-edit markers, save-as-route with participation mapping and exclusions, re-link), and the proposal document itself: review items that may hold unresolved conflicts until strict validation at apply.

## Governing

- PRD: A13, B7, B8, B9, C14 (the document half), A18 (cascades as items), I6 (the engine half).
- ARCHITECTURE: Engine > File format; Model (Proposal); Upgrade, save-as-route, re-link; Write path (strict validation at apply).
- PRACTICES: Errors, panics, and rejections (complete rejections).

## Scope

In: import with path matching against a base version and a host-supplied key allocator, and deterministic export (A13); review items (mutation, conflict with resolutions and the chosen one, orphan keep-or-remove, participation mapping, exclusion); `resolve(proposal) -> Result<Patch, Unresolved>`; `upgrade`, `save_as_route`, `relink`; `preview(domain, proposal, inputs)` for the browser's diff over any destination (a journey, a route draft, the deployment, or an empty revision-0 destination), with the derived frontier for journeys.

Out: proposal storage, ids, revisions, and the stale-base flow (3.1, 4.8); the review screen (5.7); assistant-drafted proposals (4.4 produces ordinary documents).

## Acceptance

- Behavior by id: A13 (import of an edited export matches every unchanged node by path and keeps its key; a moved node keeps its key; an unknown path mints a new key), B7 (each merge outcome; each orphan and conflict resolution; a violation becomes an unresolved conflict, never a silent apply), B8 (each mapping choice), B9 (round trip after B8), C14 (data side), I6 (a resolved proposal applies atomically through 2.1).
- Properties: export then import is identity; two exports of one graph are byte-identical; upgrading a journey with no local edits to its own version is empty; save-as-route then journey-create from the published version reproduces the structure by key.
- Planted bug: re-add a tombstoned node on upgrade and show the tombstone scenario fail.
- Fixtures: the vendor evaluation gains a version 2 (one node renamed, one removed, one added, one condition changed); its README states the expected proposal items.

## Decisions left to the implementer

- The review-item enum's shape and how a choice is recorded.
- Field-level diff granularity (per A1a field is expected; resources and participations by identity).

## Decision log

Appended by the implementer.

- Calls that shape the design are in `decisions/`: review items resolve into mutations and only an unresolved one blocks apply; the upgrade mutation applies the merge's clean outcomes and conflicts ride after it; re-link sets lineage, provenance, and markers in one mutation, and save-as-route maps entities per participation.
- Cost at the limits, stated before code: the merge compares three key-indexed graphs already in memory: per shared node 22 fields, up to 64 edges a side, up to 33 participation kinds, and its resources, each O(log n), about 4.3e5 comparisons at 2,000 nodes, plus one tree build of the target for new nodes and one scan of the merged nodes per removed role or kind (at most 64 x 2,000); memory is one clone of the journey graph (at most 16 MiB serialized). Drafting adds one trial apply (one validation and derive); a preview, one apply and two derives. `tests/cost_upgrade.rs` measures it: in a debug build the merge adds about 0.3 s to a 3.7 s apply at 2,000 nodes (`briefs/proof/2.7/README.md`).
- Layout: `cairn_engine::format` (`import` against a base, `from_file`, `export` with a `RouteHeading`, `content` for a draft opened by an import or a save), `cairn_engine::upgrade` (`merge` the core, `upgrade`, `save_as_route`, `relink`, `DraftError`), `cairn_engine::proposal` (`resolve`, `resolve_partial`, `preview`). `resolve` returns the mutations rather than a `Patch`: the host gives the patch its id and target. Schema: `Conflict`, `Kept`, `RoleReference`, `UnresolvedItem`, `UnresolvedReason`, `ProposalPreview`, the extended `ConflictResolution` and `ReviewItem`, and `ViolationCode::UnresolvedReviewItem`.
- Import matches a keyless resource by title among its node's base resources, and a keyless role or kind by id; a file whose `extends` names a version is matched against that version (the host loads it). Export sorts nodes by path (parents first), roles and kinds by id, and keeps every key.
- The merge's review items: field conflicts per A1a field; edges, participations, and resources by identity; a kind or answer-type change is one whole-node conflict; a choice change that drops an answered choice is an answer conflict rather than a field conflict. A role or kind the route removed but the journey uses starts resolved to keep (B7: nothing dangles). A save's trial apply drops every entity, so its violations are the structure's own.
- Edits outside the engine and schema crates: `crates/store/src/build.rs` and `crates/store/src/build/every.rs` (the orphan item's new `removal` in the proposals the conformance cases build), `fixtures/vendor-evaluation/route-v2.yaml` and `fixtures/README.md`, `ARCHITECTURE.md` (Upgrade, save-as-route, re-link), `decisions/`, and this brief. `cairn_schema::BoundedVec` gains `as_mut_slice`.
- A schema strategy recursed: a violation's chains carry mutations, which carry proposals, whose new violation items carried violations; the item's strategy builds a chainless violation.
- Planted bug: a base node the journey no longer holds re-added from the target fails the tombstone scenario (`thread 'tombstoned_nodes_are_not_re_added' panicked at crates/engine/tests/upgrade.rs:64:37`, the re-added keys rejected as `RetiredKeyReused`); restored, all pass.
- Review round 1 (Opus): orphan removals were computed one full walk each (54.7 s to draft 1,999 orphans in a debug build); they now come from one tree and one index of edges and notes, O(n log n + edges) plus each subtree (5.0 s, nearly all of it the trial apply), and `tests/cost_upgrade.rs` gained the orphan-heavy case.
- Review round 1 (Opus), the rest: a role or kind resolution leaves alone each reference another chosen item already rewrites (a participation or resource taken from the route, a node replaced whole or removed as an orphan, a `fills_role` or the default owner taken), so no two items write one record; keeping the journey's side of a node aspect marks it; message drafts are role references (`RoleReference::Draft`), remapped to the other role's placeholder or written out as the role's name; a route value naming a node the journey removed is a field conflict, on a shared node (its value kept) or a new one (added without the reference); a removed choice mapped onto a chosen one merges into it.
- Review round 2 (Opus): a kind item that removes or moves a participation claims it, so the role item leaves it alone, and a moved participation naming a removed role carries that role's chosen fate; every removed role's rewrite of one message draft goes into one edit; a route message draft whose answer placeholders name a node the journey will not hold is a resource conflict; a conflict whose route side names such a node is marked `dangling` and offers only the journey's side (`Conflict::offers`); a save-as-route behind its route lists each retired key with its remedy.
