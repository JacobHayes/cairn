# 6.2: Durability testbed

| | |
|---|---|
| Id | 6.2 |
| Crates or packages | `testbeds/durability` |
| Depends on | 4.1 |

## Goal

Simulation track: exploratory and non-blocking (README, Order). The service on the real Turso store under filesystem faults (EIO, short writes, crash-restart with torn writes), checking that after every restart state equals the replayed log and no acknowledged commit is missing.

## Governing

- PRD: J2, J3, A17.
- PRACTICES: Simulation with `patina` (the `durability` paragraph; the honesty rules).
- ARCHITECTURE: Storage > Backends (Turso).

## Scope

In: a `main` running the service on the Turso store in a simulated filesystem, driving commits, crashing and restarting on a seed-chosen schedule, reloading every domain and replaying its events through the engine; `always!` for the invariants; `sometimes!` that a crash landed between state rows and events and that a torn write was repaired on recovery; `mise run sim` and `cargo-patina` if 1.3 has not landed; a README.

Out: network faults (6.1).

## Acceptance

- A campaign passes with every `sometimes!` fired.
- Planted bug: write events outside the state transaction, get a failing seed that minimizes to the crash point, and rewrite it as a conformance case in 3.1's suite.

## Decisions left to the implementer

- Crash schedule, fault rates, whether to reuse 6.1's actors.
