## Goal

The node detail panel every later screen opens: everything C8 lists, every derived value with its explanation from the locally derived document, every date as pin, actual, or derived with its chain and the pin or rule to edit, per-kind actions, notes and links with artifact designation, resources with rendered message drafts, and inline resolution of a date conflict against a rejected patch.

## Governing

- PRD: C8, F5 (inline resolution moves), F7 (presentation), G1, G2, G3, A10, B5, D4 (guard failures and bypass), E3 (a decision-driven value routes through its decision, and the UI says so).
- ARCHITECTURE: Web UI (Data flow, Previews).
- PRACTICES: Code conventions (TypeScript).

## Scope

In: `NodeDetail` taking a node key, a component per C8 section, each action a one-mutation patch through 4.6's write path with the rejection shown inline; `DateConflictResolver` offering the F5 moves as patches; `AttachmentList`, its editor, and `ResourceList` with `render_draft` and copy; a temporary host screen listing a journey's nodes so the panel is reachable before the canvas exists (5.2 replaces it).

Out: the canvas, lists, proposal review, journey-level notes (5.5).

## Acceptance

- Behavior by id: C8 (every listed item), F5, F7, G1, G2, G3, A10, B5, D4, E3.
- Playwright: open the fixture's final report and read its due chain; pin a later date, see the rejection, resolve with a listed move; designate an artifact and complete; remove it and see `stale`.
- Planted bug: hide the chain on derived dates and show the F7 test fail.

## Decisions left to the implementer

- Panel layout (side panel is expected), markdown renderer, history paging in the panel.

## Decision log

Appended by the implementer.

- Layout: a side panel beside the journey's node list (the temporary host screen, `screens/JourneyPage.tsx`, at `/journeys/<id>/nodes/<key>`), sticky and scrolling on its own on a wide screen, above the list on one narrower than 52rem, where opening a node scrolls the panel into view. Sections are `<details>`: the header, actions, description or decision, contents, notes, resources, and dates start open; relevance, blocking, priority, participations, and history start folded (progressive disclosure), and blocking opens itself when the node is stale.
- Markdown renderer: a small one of our own (`ui/markdown.tsx`), paragraphs, headings, lists, quotes, fences, inline code, emphasis, and links, rendered to React elements, never HTML, with links only to http(s) and mailto. No dependency: a full renderer plus a sanitizer is two packages for what notes use.
- History paging: read from the host only when the section is opened, a page at a time with "More", a patch split across pages joined back; the first page is read again when the journey moves while it is open.
- `blocked` is not a field of the derive: the panel reads it as in scope, not finished, with a `blocked_by` or `blocked_through` entry (`model.ts` `isBlocked`), since a finished or not-relevant node's `blocked_by` lists what it holds back beneath it. D1's transition table is mirrored in `model.ts` for the buttons; the engine stays the authority and rejects anything else.
- Each section holds its own write path (`detail/write.ts`), so a rejection shows beside the action that caused it; forms (pin, snooze, force include, weight, participation, answer, note or link) are drafts kept in session storage with the revision their author saw ([`decisions/2026-10-06-an-edit-is-drafted-against-the-revision-its-author-saw.md`](../decisions/2026-10-06-an-edit-is-drafted-against-the-revision-its-author-saw.md)), keyed by form, journey, and node.
- A patch names the deployment revision only when it writes an entity reference (an entity answer, explicit participants, a role fill), E6's case.
- Out of scope here and left for later screens: editing a rule, estimate, or requirement from the "what to edit" line (5.6, authoring); a recorded date edit; agent identities in history are shown by id.
- Earlier work changed: `briefs/proof/4.6/prove.sh` now runs only `proof/shell.proof.ts`, so 4.6's proof does not pick up this brief's pictures. `Session` exposes its deriver; `Host` gains `history` and `Deriver` gains `renderDraft` (fakes updated). Vitest also runs `*.test.tsx`, components rendered to static markup.
- Planted bug: derived dates rendered without their chain (`DatesSection.tsx`), caught by F7's unit test: `FAIL src/detail/DatesSection.test.tsx > DatesSection (F7) > shows a derived date with its chain ... AssertionError: expected +0 to be 1`.
- Review (gpt-6.1-sol, high), three rounds, every finding valid and fixed on top of the stack: the panel keyed by journey and node (a draft followed into another node's panel); rejections, skip and bypass reasons kept across a reload; only the latest history read shown; a resolution or bypass sent against the revisions its edit was drafted against (it overwrote a pin set meanwhile), the deployment revision among them (E6); entity answers read through merge aliases; decided and reached children counted finished; relevance by a node's own condition; a fed milestone's pin only while its decision's answer is in effect; contributor lists longer than the derive's cap paged from the worker.
