## Goal

Simulation track: exploratory and non-blocking (README, Order). Many virtual clients issuing patches to one journey through faults, using the real H5 retry, checking that every acknowledged patch is visible, none is applied twice, revisions are gap-free, replay equals state, and every view catches up (H6).

## Governing

- PRD: H5, H6, A17, I6 (duplicate proposal submission by id), J2, J3.
- PRACTICES: Simulation with `patina` (Testbeds; the honesty rules).
- ARCHITECTURE: Storage > Concurrency and notification.
- 1.3's decision on whether clients drive the real HTTP server or call the service in-process.

## Scope

In: a `main` building a `Service` on the Turso store, N client threads with 4.2's retry and subscription logic (over HTTP and SSE, or in-process if 1.3 chose the fallback), `always!` for each invariant, including every subscriber reaching the store's revision within the coalescing interval after writes stop; `sometimes!` for a retried conflict, a surfaced overlapping conflict, a coalesced tick, and a deployment tick after an entity merge; a README.

Out: durability faults (6.2).

## Acceptance

- A campaign over the local seed count passes with every `sometimes!` fired.
- Planted bug: break the revision check, get a failing seed that minimizes to the conflict, and rewrite it as an ordinary test in the service's tests.

## Decisions left to the implementer

- Client behavior mix, N, virtual duration, fault rates.
