## Goal

Simulation track: exploratory and non-blocking (README, Order). Find out, with real runs, whether the patina native shim can run tokio with axum and an HTTP client. The answer decides whether 6.1 drives the real HTTP server. The output is a report and a recorded decision, not a feature.

## Governing

- PRACTICES: Simulation with `patina` (Testbeds, the `durability` paragraph, Tooling).

## Scope

In: one minimal program running an axum server and a tokio HTTP client exchanging requests, under `cargo patina audit` and a faulted campaign (dropped and delayed connections). Turso is pure Rust and known to run under the shim, so it needs no spike. A `README.md` with the commands, build flags, and output. No Cairn crates; patina is read-only.

## Acceptance

- The report exists with actual command output, and the decision log records whether 6.1 drives the real HTTP server or the fallback (in-process service calls driven by 4.2's transport-independent retry and subscription logic), and why.
- Instead of a planted bug: the report shows an injected fault visibly changing a run's outcome, proving faults reach the component.
- Adds `mise run sim` and `cargo-patina` at a pinned revision, with the spike as a smoke campaign over a handful of seeds, and its nightly CI job, outside the gate.

## Decisions left to the implementer

All of them.

## Decision log

Appended by the implementer.

- Answer: 6.1 drives the real HTTP server, on one current-thread tokio runtime with a 1 ms ticker task and network faults as explicit knobs; multi-thread tokio aborts the shim. Evidence and the three patina gaps: `testbeds/spike/README.md`; the calls: [`decisions/2026-10-06-6-1-drives-the-real-http-server-on-one-current-thread.md`](../decisions/2026-10-06-6-1-drives-the-real-http-server-on-one-current-thread.md) and three entries tagged patina ([`decisions/2026-10-06-patina-tokio-i-o-on-more-than-one-thread-aborts-the-shim.md`](../decisions/2026-10-06-patina-tokio-i-o-on-more-than-one-thread-aborts-the-shim.md), [`decisions/2026-10-06-patina-a-delayed-tcp-segment-does-not-wake-epoll-wait.md`](../decisions/2026-10-06-patina-a-delayed-tcp-segment-does-not-wake-epoll-wait.md), [`decisions/2026-10-06-patina-campaign-faults-is-unusable-for-a-tcp-only-guest.md`](../decisions/2026-10-06-patina-campaign-faults-is-unusable-for-a-tcp-only-guest.md)). 6.1's scope now says client tasks, not threads, and PRACTICES' Testbeds paragraph records the answer.
- `testbeds/spike` is its own Cargo workspace (an empty `[workspace]` table): `cargo patina build` resolves only its tree, its tokio, axum, and hyper never enter the root `Cargo.lock`, and the check ladder (root members `crates/*`) never builds it. It cannot inherit `[workspace.lints]`, so it repeats the crate-wide set in `[lints]`, picks up the root `clippy.toml` by directory, and `sim.sh` runs rustfmt, clippy with warnings denied, and its unit tests, since rung 1 does not see it.
- Stack: axum 0.8 (`http1`, `tokio` features only), hyper 1 client connections over `tokio::net::TcpStream` (no pool, no DNS, IP literals), tokio pinned `=1.53.1` (the version patina's own tokio testbeds prove), `patina-dst` at the workspace pin. A fresh connection per attempt, so resets and refusals hit connect, send, and receive alike.
- Outcomes through the verdict channel (`pass` under `spike-outcome`, `violation` per invariant), echoed as `SPIKE_*` lines; exit 3 (abort intent) and 4 (liveness, no verdict) avoid 2, which patina reserves for CLI errors.
- `mise run sim` is `mise-tasks/sim`, which runs every `testbeds/*/sim.sh` and fails when cargo-patina is missing or no testbed has one, so 6.1 and 6.2 join by adding a script. The spike's legs: code checks, build, audit with no allowance, determinism (repeats byte-identical, replay reproduces the verdict), a 16-generation `--buggify --sched-pct` campaign, an 8-seed faulted `explore` sweep that must show every run retrying and no inert knob, and one strict-xfail leg per patina gap.
- cargo-patina is a mise cargo-backend tool at the SDK's revision (`version = "rev:<sha>"`, `crate = "cargo-patina"`, `locked`); PRACTICES' Tooling example had the wrong option shape and now shows this one. CI's `check` and `nightly` jobs set `MISE_DISABLE_TOOLS` to skip building it; the new `sim` job (schedule and manual dispatch, Linux) builds it.
- Not proven: TLS, DNS names, SSE and other streaming responses, HTTP/2, reqwest. Blocking `std::net` client threads beside a current-thread tokio server pass under latency in a reproducer but are not built into the spike.
- Instead of a planted bug (AGENTS): `--bug no-dedupe` passes fault-free and fails under `--net-reset-permille 100` with `PATINA_VERDICT seq=0 kind=violation label=applied-once detail=0-3\sapplied\s2\stimes` (`briefs/proof/1.3/README.md`). The unit test of the judge was also planted against: `if *times > 2` in `applied-once` fails `violations_name_the_broken_invariants` with `assertion left == right failed: applied twice; left: []; right: ["applied-once"]`, and passes once restored.
- Checks: `mise run sim` passes (about 15 s); `mise run check` passes (`ladder: check passed: rungs 1`); `actionlint` and `shellcheck` pass on the workflow and scripts.
