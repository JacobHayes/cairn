# 5.5: Journey index and overview, route screens, entities, identity

| | |
|---|---|
| Id | 5.5 |
| Crates or packages | `web/app` |
| Depends on | 5.3 |

## Goal

The screens around a journey: the journey index with its filters and the cross-journey "mine" list; the journey overview with status, lineage, journey-level notes and links, and complete and archive; journey creation from a route version or empty, landing in 5.3's walkthrough; route list and route detail with versions, their journeys, and upgrade availability, plus draft open, publish, discard, retire, import, and export; entity management, including entity emails and the offer to merge duplicates; the user's identity screen.

## Governing

- PRD: C16, C17, B1, B3, B11, A11, A13, A19, E6, H3, G1 (journey-level); Success criteria.
- ARCHITECTURE: Web UI (Screens); Auth (users and identities); Terms (Capabilities document).
- PRACTICES: Code conventions (TypeScript).

## Scope

In: the screens above and the application's navigation; "upgrade available" rendered from 3.1's index filter, never computed in the UI.

Out: the canvas and acting surfaces; the upgrade, save-as-route, and re-link flows (5.7 adds their entry points here).

## Acceptance

- Behavior by id: C16, C17 (a route with three versions, journeys on each, and a retired route still offering upgrades), B1, B11, A11, A13, A19 (hard delete needs a typed confirmation), B3, E6, H3, G1.
- Playwright: create a journey from the fixture route and land in the walkthrough; complete and archive; import the fixture file and export it identically; merge two entities with history intact; link an identity against the server host with 3.2's stub issuer.
- H6 in Playwright on the server host: a new journey appears in another page's index; an entity merge changes an owner shown on another page.
- Planted bug: hide "upgrade available" on retired routes and show the C17 retired-route case fail. Separately, a client contract test asserts the screen reads the server's field.
