# 8.10: Plan list and timeline

| | |
|---|---|
| Id | 8.10 |
| Crates or packages | `crates/schema`, `crates/engine`, `crates/api`, `openapi/`, `web/client`, `web/wasm`, `web/app` |
| Depends on | 8.6, 8.1; the Affects column 8.3 |

## Goal

Give the Plan page a list and a timeline that read the same tree the graph does. Today the list is a flat table, the decisions page is its own screen with an affects table, and the timeline is a flat list of dated rows with no sense of structure. The Plan list is a tree grouped by container, folded to the top level, that flattens when sorted; with the decisions toggle it becomes the decision table. The timeline's rows follow the containment tree, fold with the same detail steps, and show float and dependencies only for the selected row.

## Governing

- PRD: C9 (filters, sorts, search, bulk; tree by default; display state), C12 (the decision list: answer, rationale, nodes affected), C13 (rows by containment, the undated list, the end anchor), D8, F7 (dates explained), B6 (bulk snooze of a container).
- ARCHITECTURE: Web UI (Data flow: projections run in the worker).
- DESIGN: Approachable by default; Components (Table, Status, Dates, Selection bar); Charts.
- PRACTICES: Code conventions.

## Scope

In:
- The Plan list as a tree table, the region's one scroller with a sticky header: grouped by container and folded to depth one, containers showing progress and at most one roll-up badge; opening every level gives the flat C9 table. Sorting by any column (rank, slack, gravity, unblocks, due) flattens it and shows each row's container under its title. Default columns Status, Title, Owner, Due (in words); Columns adds Rank, Start by, Slack, Gravity, Unblocks (count, then the weighted value in words), Kind, Answer, Why, Affects, Effort. Rows read `display_state`; the "by state" filter covers display states. Not-relevant rows are hidden by default, with their count in the header and a filter to show them; conditional rows are shown. Text search over title, description, notes, and resources.
- With decisions on, the rows are decisions with the columns Status, Decision, Answer, Why (the rationale's first paragraph as plain text, one line), Affects ("brings in 6, drops 3", a link that selects and traces on the graph; with 8.3), Owner, Decide by.
- Bulk: hover checkboxes bring up the selection bar shared with 8.8; one patch, and a guard failure on any row names which. Snoozing a container in bulk uses 7.4 once it lands.
- The timeline: rows are the containment tree, folded by the same detail steps as the graph; a collapsed stage is one bar from its earliest start to its latest due, filled by done over total. A work bar runs from latest start to due, or is a tick at due with no estimate; decisions are diamonds at their decide-by date; milestones are filled diamonds at their effective date labeled pinned, estimated, or reached; overdue is an error hatch with its words ("3 days late"); today is a dashed accent line. Selecting a row shows its float (earliest to latest start) and its dependency lines in the trace styles; a shortfall item draws its chain in error ink. Nodes with no date gather in a folded list. The final milestone anchors the right edge; without one, or one with no date yet, the axis ends after the latest date and says there is no end anchor. Bar styles follow display state (finished in the ramp, conditional dashed).
- Timeline input: two-finger horizontal scroll pans time, vertical scroll moves rows, a pinch zooms the time axis; a range control (fit, month, quarter).

Out: the graph (8.8); the decision's inspector (8.7).

## Decisions left to the implementer

- How deep the timeline folds at each detail step when a stage holds nested groups.
- Whether the range control remembers its choice per journey.

## Decision log

- The list asks the engine for display states (`ListQuery.display_states`, the `display_state`
  query parameter; additive), so the not-relevant rows are left out by leaving that state out of
  the request. The by-state filter in the address reads display states; an old stored-state value
  in an address is dropped.
- The timeline folds by the graph's detail steps (Stages, Decisions, Work, All). At Stages a
  stage that holds current work (the acting frontier or an active node) opens to its work and
  the others are one bar; the other steps show their kinds all the way down. A stage's own fold
  flips what its step would do, and a selected row's containers stay open.
- The range control (Fit, Month, Quarter) keeps its choice in the address, not per journey.
- Gravity on a container row is its subtree gravity; rank shows the node's place in the order.
