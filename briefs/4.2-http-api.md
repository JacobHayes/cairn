# 4.2: HTTP API, OpenAPI, SSE, TypeScript client

| | |
|---|---|
| Id | 4.2 |
| Crates or packages | `crates/api`, `openapi/` (generated), `web/client` |
| Depends on | 4.1, 3.2 |

## Goal

The API for every service operation 4.1 offers: domain patches, one write verb per domain, the store-backed reads, the domain document, the SSE revision stream, and capabilities, with Rust types as the source of truth for the generated OpenAPI document and TypeScript client types. The endpoints for projections, proposals, and route files join with 4.9 (DECISIONS.md: the service and API split at the engine's 2.4 boundary). The hand-written TypeScript wrapper (safe retry, subscriptions) needs the touched-set function through wasm, so it lands with 4.6.

## Governing

- PRD: I1, J5, A15, H5 (client-side safe retry), H6; Non-functional: Observable.
- ARCHITECTURE: HTTP API; Generated artifacts; Observability; Repository layout (`web/client`); Terms (Domain document).
- PRACTICES: Errors, panics, and rejections; Explicit limits (request body, request duration, in-flight requests, SSE).

## Scope

In: the ARCHITECTURE endpoints for 4.1's operations (`POST /{domain}/patches`; journeys, routes, versions, the deployment and its entities, users, events, the journey index, route detail, search, capabilities); `/document` (graph and state, the derive inputs, and the engine version; moved from 2.6 since it needs no derived value: this brief adds its constructor to the engine's `project` module and the service read that calls it); error bodies as 1.2's rejection and conflict; the auth layer from 3.2; SSE with current revisions first, heartbeat, and the subscriber limit; OpenAPI generated into `openapi/`; `web/client/generated/`; the H5 safe retry and the subscription tracking as transport-independent logic, wrapped by the progenitor Rust client, so 6.1 can drive the same logic in-process; the Rust client used by tests here and by 6.1; tracing and metrics on every handler.

Out: the projection, proposal, import, export, upgrade, save-as-route, and re-link endpoints (4.9); the listener and binary (4.7); MCP (4.3); assistant endpoints (4.4 mounts its own).

## Acceptance

- I1 (a coverage test asserts every service operation has an endpoint), J5, A15 (three violations arrive as three), H5 (the Rust client retries a non-overlapping conflict and surfaces an overlapping one, including a subtree removal against an edit inside it), H6 (two clients on one journey; a late subscriber; an entity merge ticks the deployment), `/document` (it carries no derived value, and deriving it with the engine gives what the server derives at the same inputs).
- Planted bug: change a response type without regenerating and show rung 5 fail.
