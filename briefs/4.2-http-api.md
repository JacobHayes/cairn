# 4.2: HTTP API, OpenAPI, SSE, TypeScript client

| | |
|---|---|

## Goal

The API for every service operation 4.1 offers: domain patches, one write verb per domain, the store-backed reads, the domain document, the SSE revision stream, and capabilities, with Rust types as the source of truth for the generated OpenAPI document and TypeScript client types. The endpoints for projections, proposals, and route files join with 4.9 (DECISIONS.md: the service and API split at the engine's 2.4 boundary). The hand-written TypeScript wrapper (safe retry, subscriptions) needs the touched-set function through wasm, so it lands with 4.6.

## Governing

- PRD: I1, J5, A15, H5 (client-side safe retry), H6; Non-functional: Observable.
- ARCHITECTURE: HTTP API; Generated artifacts; Observability; Repository layout (`web/client`); Terms (Domain document).
- PRACTICES: Errors, panics, and rejections; Explicit limits (request body, request duration, in-flight requests, SSE).

## Scope

In: the ARCHITECTURE endpoints for 4.1's operations (`POST /{domain}/patches`; journeys, routes, versions, the deployment and its entities, users, events, the journey index, route detail, search, capabilities); `/document` (graph and state, the derive inputs, and the engine version; moved from 2.6 since it needs no derived value: 2.6 landed first with the constructor, `project::document`, so this brief adds the service read that calls it); error bodies as 1.2's rejection and conflict; the auth layer from 3.2; SSE with current revisions first, heartbeat, and the subscriber limit; OpenAPI generated into `openapi/`; `web/client/generated/`; the H5 safe retry and the subscription tracking as transport-independent logic, wrapped by the Rust client (hand-written over the shared types, DECISIONS.md), so 6.1 can drive the same logic in-process; the Rust client used by tests here and by 6.1; tracing and metrics on every handler.

Out: the projection, proposal, import, export, upgrade, save-as-route, and re-link endpoints (4.9); the listener and binary (4.7); MCP (4.3); assistant endpoints (4.4 mounts its own).

## Decision log

Appended by the implementer.

- Planted bug: `Capabilities` given a field without `mise run gen`, `mise run check:5` failed with `ladder: rung 5: FAILED: generated files differ from their sources` (`openapi/cairn.json` and `web/client/generated/api.ts` changed); restored, it passes (`briefs/proof/4.2/`).
- URL spellings: `/{journeys,routes}/{id}/patches` and `/deployment/patches`; route detail (C17) at `GET /routes/{id}/versions`, one version at `/routes/{id}/versions/{version}`; the caller at `GET /users/me` with agent tokens under `/users/me/tokens` (mint, list, revoke: 3.2's `Accounts` operations, which the UI offers, so I1 wants them here); the stream at `GET /events/stream?domain=...` with `deployment`, `journey:<id>`, `route:<id>`, `proposal:<id>`, `journeys`, `routes`, `proposals`; an event log filter `log=` in the same spelling.
- Pagination: `after` (the previous page's `next`) and `size` (1 to the page limit, larger cut to it); each page body is `{items, next}`. Query parameters are declared once per endpoint (`query.rs`), parsed by the handler and described by the OpenAPI document from the same table; one an endpoint does not declare is refused 400 rather than ignored.
- Errors: a rejected patch is its `Rejection` unchanged, 422 when invalid, 409 when stale or reusing a patch id; everything else is a `Problem` (`error`, `message`, `request_id`), 503 with `Retry-After` for every limit (in flight, subscribers, store connections, request duration). The auth layer's own 401/403 stay its text bodies with the `WWW-Authenticate` challenge (3.2).
- A body must be `application/json` (415 otherwise), so a cross-site form cannot carry a session cookie's write without a CORS preflight.
- Heartbeat: an SSE comment after 10 s quiet (`SSE_HEARTBEAT_INTERVAL`, a constant, not a limit, asserted under the 15 s write stall). The stall is enforced by a one-frame channel between the pump task and the body: a send that waits out `SSE_WRITE_STALL` drops the subscription (freeing its place under the subscriber limit) and ends the body in an error. A subscriber that disconnects is dropped at once (the pump watches the channel close).
- Metrics: the `metrics` facade (counters and histograms the binary's exporter, 4.7, reads): requests by endpoint, method, and status; latency by endpoint; patches by outcome; engine panics. Derive and commit durations sit inside the service and are not measured here. Logs: one `tracing` span per request with its id, method, and endpoint, a line when answered, and one per patch with its id, domain, and outcome.
- The engine version a domain document carries is the engine crate's version, which a release raises.
- The Rust client is `cairn_api::client`: a transport (one HTTP/1.1 connection per request over tokio, with an observer the proof's transcripts use), SSE reading, the typed `Client`, and the transport-free `retry` and `tracker`; `client::in_process::patch` runs the same retry against the service. The test sign-in provider in `tests/support` stands for any provider vouching for a verified email, since two dev providers with tokens refuse each other's.
- Edits outside the brief's paths: the service's `document` read (`crates/service/src/document.rs`, one `mod` line in `lib.rs`) and an engine test of 2.6's `project::document` (`crates/engine/tests/document.rs`); rungs 1, 2, and 4 (TypeScript checks; the in-process API suite moved from rung 2 to 4); `mise-tasks/gen/openapi`; `clippy.toml` (OpenAPI and TypeScript as doc words); the CI workflow (`npm ci`); root `package.json`, `tsconfig.json`, `eslint.config.js`; ARCHITECTURE's HTTP API and layout lines (DECISIONS.md).
- Landing on main after 2.6: 2.6's `project::document(&Journey, &DeriveInputs)` is the one constructor (ARCHITECTURE, Engine > Projections), so 4.2's copy is gone and the service read calls 2.6's; the engine test that deriving the document gives what the host derives now covers 2.6's function. 4.1's review fixes made a subscription's first take `Take::Current`, the complete current set; the stream sends it as ticks like any other, so a domain deleted while a client was away starts at revision 0.
- Review round 1 (Opus): the tracker forgets a refetch that failed or a stream that reopened (`refetch_failed`, `reopened`), so a fault never leaves a view stale; path segments that cannot be read answer a problem; the OpenAPI document lists the auth layer's text 401, 403, and 503; the request duration limit wraps the API's routes inside the auth layer, not auth's routes, and a patch runs on its own task so a timeout never cuts a commit off before its announcement; the SSE write stall at the socket is the listener's `TCP_USER_TIMEOUT`, in 4.7's scope (DECISIONS.md). A 405 is not documented per operation: it answers a method the document does not list.
