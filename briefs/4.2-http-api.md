# 4.2: HTTP API, OpenAPI, SSE, TypeScript client

| | |
|---|---|
| Id | 4.2 |
| Crates or packages | `crates/api`, `openapi/` (generated), `web/client` |
| Depends on | 4.1, 3.2 |

## Goal

The complete API: every service operation as an endpoint, one write verb per domain, proposals, the SSE revision stream, capabilities, and Rust types as the source of truth for the generated OpenAPI document and TypeScript client types. The hand-written TypeScript wrapper (safe retry, subscriptions) needs the touched-set function through wasm, so it lands with 4.6.

## Governing

- PRD: I1, I3, J5, A13, A15, C14, H5 (client-side safe retry), H6; Non-functional: Observable.
- ARCHITECTURE: HTTP API; Generated artifacts; Observability; Repository layout (`web/client`).
- PRACTICES: Errors, panics, and rejections; Explicit limits (request body, request duration, in-flight requests, SSE).

## Scope

In: the endpoints ARCHITECTURE lists, including `/document` (graph and state) and node detail with capped, pageable explanations; error bodies as 1.2's rejection and conflict; the auth layer from 3.2; SSE with current revisions first, heartbeat, and the subscriber limit; OpenAPI generated into `openapi/`; `web/client/generated/`; the H5 safe retry and the subscription tracking as transport-independent logic, wrapped by the progenitor Rust client, so 6.1 can drive the same logic in-process; the Rust client used by tests here and by 6.1; tracing and metrics on every handler.

Out: the listener and binary (4.7); MCP (4.3); assistant endpoints (4.4 mounts its own).

## Acceptance

- I1 (a coverage test asserts every service operation has an endpoint), I3, J5, A15 (three violations arrive as three), H5 (the Rust client retries a non-overlapping conflict and surfaces an overlapping one, including a subtree removal against an edit inside it), H6 (two clients on one journey; a late subscriber; an entity merge ticks the deployment), A13, C14.
- Planted bug: change a response type without regenerating and show rung 5 fail.
