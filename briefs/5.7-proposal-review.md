| | |
|---|---|

## Goal

Proposal review as a diff over the canvas and as an editable list, with a local preview of the resulting frontier, apply, discard, and the stale-base refresh; and the flows that create proposals: upgrade, save-as-route, re-link, and breakdown. This brief also adds their entry points to earlier screens.

## Governing

- PRD: C14, B7, B8, B9, B10 (break down opens a proposal), A18, I6, C17.
- ARCHITECTURE: Web UI (Previews); Engine > Upgrade, save-as-route, re-link; Engine > Model (Proposal).
- PRACTICES: Code conventions (TypeScript).

## Scope

In: proposal screens for every destination (journeys, routes, the deployment, and a journey or route the proposal creates at revision 0), with the frontier preview only for journeys; `ProposalEditor` over 2.7's documents using 5.6's editors and 5.1's date resolver, previewing through wasm `preview` and drawing on 5.2's `CanvasOverlay`; the upgrade, save-as-route, and re-link flows with entry points on 5.5's overview; "break down" on 5.3's triage card and on 5.1's panel.

Out: producing proposals server-side (2.7, 4.1, 4.4); the assistant panel (5.8).

## Acceptance

- Behavior by id: C14 (every item type editable; preview shows the resulting frontier), B7, B8, B9, B10, A18, I6 (a stale proposal shows the intervening events and blocks apply until refreshed and re-reviewed).
- Playwright over the fixture's version 2: upgrade the scenario journey, resolve each conflict type, apply; save the routeless fixture journey as a route with a mapping and re-link it; break down the placeholder from triage.
- Planted bug: allow apply without re-review after a refresh and show the I6 test fail.
