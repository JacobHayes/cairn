# 2.6: Projections

| | |
|---|---|
| Id | 2.6 |
| Crates or packages | `crates/engine` (module `project`) |
| Depends on | 2.5 |

## Goal

Every read view the PRD names, as pure functions, so the browser (which derives locally) and the server (for agents and the API) produce the same thing.

## Governing

- PRD: C2 (visibility, hoisting, roll-ups, edge re-targeting, every badge), C5, C7, C9, C10, C12, C13, C18, E4, G3, A10, I3, J4.
- ARCHITECTURE: Engine > Projections; Terms (Domain document); Read path (explanations and their caps in server responses); Web UI (Data flow).
- PRACTICES: Explicit limits (snapshot top-N, history page, explanation entries per value in a server response).

## Scope

In: `snapshot`, `level`, `trace` (over the full structural graph), `decision_view`, `timeline`, `status_summary`, `next`, `list` with in-journey text search, `mine`, `history`, `explanations` with paging, `render_draft` over parsed segments with visible markers. All outputs are 1.2 shapes.

Out: `document`, which needs no derived value and moved to 4.2 (DECISIONS.md: the service and API split at the engine's 2.4 boundary); rendering (phase 5); cross-journey search (3.1); layout (5.2).

## Acceptance

- Behavior by id: C2 (each kind toggle's visible set, hoisting, roll-up badges, and edge collapse on the vendor evaluation, including a hidden root; a visible action whose blocking decision is hidden carries the hidden-prerequisites marker; an edge collapsing onto one node is dropped), C5 (`stalled` data), C7, C9 (each filter on a fixture state; search hits notes), C10, C12, C13, C18, E4, G3 and A10 (an unfilled role renders a marker), I3 (paging; depth and subtree scoping; counts add up; snapshot and `next` agree), J4.
- Properties: every visible edge maps to at least one underlying edge; showing more kinds never hides a node that was visible; the snapshot page never exceeds its limit; history pages are contiguous and complete.
- Planted bug: collapse edges without de-duplicating and show the C2 scenario fail.
- Fixtures: each fixture README gains the expected visible set with actions hidden and the first three next items at a stated scenario point.

## Decisions left to the implementer

- Search tokenization (case-insensitive substring is enough for v1).

## Decision log

Appended by the implementer.

- Calls that shape the design are in DECISIONS.md: what a canvas level draws, marks, and rolls up; how the snapshot scopes, pages, and agrees with the next list (with the page limit as a schema constant); history over given events with `Event::nodes`; what the decision view, timeline, status summary, list, and "mine" show.
- Layout: `cairn_engine::project` (`DerivedJourney::new(graph, derived)`, the graph and its derive) with one module per projection: `level` (C2, and the decision view's base), `trace` (C7), `next` (C9, C10, E4), `rows` (the shared `NodeRow`, sorts, and pages), `snapshot` (I3), `explain` (explanation pages and `history`), `views` (C12, C13, C18), `draft` (`render_draft`, A10, G3); `document` and `history` are free functions. Schema shapes are in `cairn_schema::projection`. An unknown key in a query is `ProjectionError::UnknownNode`.
- ARCHITECTURE's Projections list gains `render_draft` and says each projection takes a `DerivedJourney`; no other document changed. Edits outside the engine and schema crates: `fixtures/README.md` (the per-fixture projected lines), `DECISIONS.md`, `ARCHITECTURE.md`, and this brief.
- Kept-work-pending (D1a's "skipped, kept work pending"), which no schema field carried, is a level node flag: a skipped (stored or effective), in-scope node that does not yet satisfy dependencies.
- `RankTerms` crosses the API as its own schema type (four terms and the rank, as `Real`s); a row's leverage is the ranking's (the viewer's, in "prioritize for me").
- Sorting by a single signal (C9, C10) breaks ties in the ranking's order (the global one, or the viewer's); `SortBy::Effort` is 2.5's effort-adjusted order.
- A message draft's `{{journey.created_at}}` renders the deployment-local day the journey was created (`created_on`, A9), so the engine converts no time zones; `{{journey.url}}` comes from the host, which alone knows it, and is a marker when none is given. A missing placeholder reads as written in a route file (`[missing: roles.eval_owner.name]`, `[missing: answers.purpose]`).
- Search tokenization (left to the implementer): a case-insensitive substring, ASCII letters folded, as the store's cross-journey search.
- Cost at the limits: each module states its cost in operations; `tests/cost_projections.rs` runs every projection on `generated::date_limits`, checks each output's bound, and prints elapsed times (a debug build: levels about 100 ms, the snapshot about 65 ms, the rest under 35 ms; `briefs/proof/2.6/README.md`).
- Planted bug: canvas edges drawn one per underlying edge instead of collapsing onto their pair of stand-ins fails the C2 scenario (`thread 'edges_landing_on_the_same_pair_collapse_into_one' panicked at crates/engine/tests/level.rs:219:5`, `n_reporting` to `n_final_review` drawn twice, 1 of 9 failing); restored, all pass (`briefs/proof/2.6/README.md`, generated by `prove.sh`).
- Review round 1 (three P2, all valid, fixed with regression tests): a decision's effects read every condition on a node and its ancestors up to a force include, not only the one relevance names as its producer; the list's owner filter and the viewer's entities read through entity aliases (E6), through a new `Participation::canonical_entity`; a draft's entity answers name the merge survivor.
- Review round 2 (Opus; two P2 and one P3, all valid, fixed with regression tests): a decision's effects close over the decisions it affects; open decisions in the status summary and the snapshot leave out closed ones (under a skipped container); answers in the snapshot and the decision view read entity keys through aliases.
