## Goal

Create the repository so every later brief starts from a workspace that builds, lints, and runs `mise run check`, with rung 1 live and the conventions every crate inherits already enforced. Crates are created by the brief that first fills them; this brief creates none beyond what rung 1 needs to prove it works.

## Governing

- ARCHITECTURE: Repository layout; Generated artifacts; Build, run, deploy.
- PRACTICES: Code conventions; The validation ladder; Growing the ladder.
- `AGENTS.md`: Repository conventions.

## Scope

In: the Cargo and npm workspace roots; workspace lint configuration carrying the PRACTICES denied set (including `too_many_lines` at 70, `HashMap` disallowed in `crates/engine` once it exists); `mise.toml` with pinned tools (Rust toolchain, Node, the wasm tool; the patina SDK crates as git dependencies at a pinned revision) and the tasks `check`, `check:fast`, `check:N`, `gen`; rung 1; CI on push and a nightly job for rung 3 that runs only the rungs that exist (the simulation track adds `cargo-patina` and `mise run sim` itself); `.gitignore`, license, a one-screen `README.md`; the planning documents (`PRD.md`, `ARCHITECTURE.md`, `PRACTICES.md`, `AGENTS.md`, `briefs/`) moved into the repository root.

Out: any crate's content, fixtures (1.2), and every rung other than 1.

## Acceptance

- On a fresh clone, `mise install` then `mise run check` runs rung 1 and passes. A stray `unwrap`, a 71-line function, or a formatting error in the throwaway crate rung 1 lints fails it; the crate is removed once 1.2 lands.
- `mise run check` runs exactly the rungs that exist, and a rung that runs zero tests fails (PRACTICES, The validation ladder).
- Planted bug: a lint violation fails rung 1, with the output in the decision log.
- Adds rung 1.

## Decisions left to the implementer

- Workspace layout details (`[workspace.dependencies]` and `[workspace.lints]` are expected) and crate naming prefix (`cairn-engine` and so on).
- Task names below the fixed ones; how the ladder prints its summary.
- Which of `wasm-pack` or `wasm-bindgen-cli` to pin (4.5 may swap).
- CI provider specifics (GitHub Actions is expected).

## Decision log

Appended by the implementer.

- Already in place before this brief: the planning documents in the repository root, the decision log (now `decisions/`), `CLAUDE.md` as a symlink to `AGENTS.md`, and the public GitHub repository (coordinator).
- Owner's fixed choices: Apache-2.0 only; Rust 1.99.0 with `wasm32-unknown-unknown`; the patina SDK at rev `6a2977e7`; GitHub Actions on Linux runners only; npm workspaces.
- Crate prefix `cairn-`. The throwaway crate is `crates/scaffold` (`cairn-scaffold`), holding one constant; 1.2 removes it.
- A rung exists when its task file `mise-tasks/check/<N>` exists. `scripts/ladder` runs those in numeric order (`check:fast` passes 3 as the highest), stops at the first failure, and ends with a summary of every `ladder: rung N:` line. Rungs report through `scripts/ladder-lib.sh`: `ladder_suite` fails on a count of zero, `ladder_rung_end` fails a rung that reported no suite, `ladder_require_tool` fails on a missing tool.
- Rung 1 suites: crates inheriting the workspace lints, files `rustfmt` checked (from `rustfmt -v`), crates `clippy` checked (from Cargo's JSON artifact messages). It uses `node` to read `cargo metadata`, and passes `--locked`, so `Cargo.lock` is committed.
- `gen` runs every `mise-tasks/gen/<name>`; none exist yet, so it says so and succeeds.
- Tools: Node 26.10.0 (the installed 26 line, LTS from late October 2026); `wasm-bindgen-cli` 0.2.129 as prebuilt release binaries (`github:` backend), the wasm tool 4.5 may swap. `cargo-patina` is left to the simulation track.
- patina SDK pins live in `[workspace.dependencies]`; Cargo resolves none until a crate opts in, so `Cargo.lock` has no patina entry yet.
- npm workspace root covers `web/*`; its near-empty `package-lock.json` is committed so `npm ci` works from the start.
- CI: one workflow, `ubuntu-latest`, `actions/checkout@v7` and `jdx/mise-action@v5` (installs the pinned tools and fails if one does not install), `mise run check` on every push; a nightly job on a schedule runs the same rungs that exist until rung 3 lands and raises its case count there. No Cargo cache action yet: the build takes seconds.
- Proof: `briefs/proof/1.1/README.md` lists each planted rule break and what the ladder did with it.
- Tasks are mise file tasks in `mise-tasks/` rather than tables in `mise.toml`, so a rung is one file; ARCHITECTURE's Repository layout now lists `mise-tasks/` and `scripts/` beside `mise.toml`.
- `#![forbid(unsafe_code)]` is the workspace lint `unsafe_code = "forbid"`, which every crate gets because rung 1 fails a crate that does not inherit the workspace lints.
- Planted bug: `text.parse().unwrap()` in the throwaway crate fails rung 1 with `error: used `unwrap()` on a `Result` value --> crates/scaffold/src/lib.rs:14:5` and `ladder: check FAILED at rung 1`; the clean tree passes (`briefs/proof/1.1/README.md`).
- Checks: `mise run check` passes (`ladder: check passed: rungs 1`), also on a copy of only the tracked files after `mise install`; `actionlint` and `shellcheck` pass on the workflow and the task scripts.
