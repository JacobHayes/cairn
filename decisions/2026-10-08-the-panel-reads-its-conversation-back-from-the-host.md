# The panel reads its conversation back from the host, and links a turn's writes from the tab that sent it

- Question: the panel shows "a conversation per target per user" and reports direct changes "with links to the affected nodes" and proposals to review. The API answered a turn but had no read of a conversation, so a panel opened again had nothing to show; a direct write's report named its patch and revision but not the nodes it wrote; and the host keeps Cairn's report of each write as text, so a conversation read back has no proposal ids or node keys to link.
- Call: `GET /journeys/{id}/assistant` and `GET /routes/{id}/draft/assistant` answer the caller's conversation as kept (author `user`, `assistant`, or `cairn`, the time kept, the text), an ordinary read under the request duration, refused to an agent as a turn is. An applied action names the nodes it wrote (the wrapper's touched set), and Cairn's kept report names them too. The tab that sent a turn keeps its structured answer in session storage under the conversation, dated by when the host kept the answer (every report and the reply of one turn are kept at one time), and the panel shows a run of reports kept at that time, and as many as the turn answered, as the writes with their links; anything else shows as the kept text.
- Alternatives: storing each report's structure with the message (a new column on `conversation_messages` and a store migration, for what is a display convenience); finding proposal ids and node keys in the report text (couples the panel to the report's wording); keeping the conversation in the tab only (another device or tab would not see it).
- What would change it: a stored structure for each write, which would let every device link earlier writes; it fits as a nullable column beside `content`.
