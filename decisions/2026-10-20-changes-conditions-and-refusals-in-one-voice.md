# One voice for a patch's changes, a mutation, a condition and a refusal

**Question.** A patch's changes, a single mutation, a condition and a refused write are each shown on several screens. Where is each put in words?

**Call.** Each has one renderer in the web app, and every screen that shows it uses that one: a patch's changes (the history's patch list), a mutation (`mutationWords`), a condition (`conditionWords`, which says a choice by its label, a date in words and an identity by name, never an id), a refusal (`RejectionView`, which shows the engine's own words), and a write (`useWrite`, whose refusal field is `rejection` on every adapter). A shortfall is not an error and is never shown as one.

**Alternatives.** Short forms per surface, such as "Who runs testing? = Partner" on a card: a second format is the drift this prevents.

**What would change it.** The engine wording conditions itself, which the app would then read.
