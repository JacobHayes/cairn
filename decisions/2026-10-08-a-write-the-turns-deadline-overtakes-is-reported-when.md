# A write the turn's deadline overtakes is reported when it lands within half the save reserve

- Question: a tool call runs on its own task so a commit the turn's deadline overtakes still completes ([`2026-10-07-every-wait-in-a-turn-is-held-to-the-turns-limit.md`](2026-10-07-every-wait-in-a-turn-is-held-to-the-turns-limit.md)), but the turn then answered without it, so a write could land unreported, against I5's "every direct write is reported". A failed conversation save also discarded a turn's answer after its writes had landed.
- Call: when the deadline overtakes a tool call, the turn waits for it up to half the save reserve (2.5 s of the 5 s) and reports its write if it lands; a write later still is not in the answer, and the turn's ending note says a change still being written may land after it. A failed save fails the turn only when it wrote nothing; otherwise the answer and its writes are returned and only the conversation is not kept, as when the save runs out of time. Moving a note or link counts the node it leaves as well as the one it lands on, toward the ten-node limit.
- Alternatives: waiting for the overtaken call without bound (the turn's limit would no longer hold); reporting a late write in the conversation afterwards (a second save outside the turn, racing the next turn).
- What would change it: a save reserve that is needed whole in practice, or a late write that lands unreported often enough to want a follow-up report.
