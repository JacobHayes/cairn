# The configuration is one TOML file with a fixed set of environment overrides, and only the rank constants default

- Question: ARCHITECTURE asks for "a file plus environment overrides; deployment-specific values have no defaults", and PRACTICES fixes the surface (database path, listen address, public URL, auth providers with their security settings, assistant provider and credential, time zone, rank constants). Which values are deployment-specific, how a variable addresses a value in a list of providers, and what a public URL may be.
- Call: `cairn.toml` holds `database`, `listen`, `public_url`, `timezone`, an optional `[rank]` table, `[[auth]]` providers tagged by `kind` (in the order a request is put to them), and an optional `[assistant]`. The first four have no default: a missing one fails startup naming the key and the variable that can set it, every problem listed at once. The rank constants default to the PRD's (Priority calls them defaults) and are checked at startup: each weight finite and non-negative, the four blend weights summing to one, the undecided discount from 0 to 1, the other-owner factor from 1 to the weight limit, the horizon from 1 to the date offset limit (365 days). At least one auth provider is required, names distinct, at most one built-in OAuth server (its metadata sits at the origin's well-known paths), whose `sign_in_with` names an OIDC provider (the only kind with a sign-in page); the security settings (`auto_link`, `allow_off_loopback`) default off. Overrides are a fixed table, not a generic mapping: `CAIRN_DATABASE`, `CAIRN_LISTEN`, `CAIRN_PUBLIC_URL`, `CAIRN_TIMEZONE`, `CAIRN_ASSISTANT_API_KEY`, and `CAIRN_AUTH_<NAME>_TOKEN` or `_CLIENT_SECRET` for a named provider's secret; a secret variable that names nothing fails startup. The public URL must be http or https with a host, no credentials, query, or fragment, and the root path, since the API and the UI share the root of one origin (4.6). Unknown keys fail. The time zone is read from the system's zone database (`jiff` with `tzdb-zoneinfo`).
- Alternatives: a generic `CAIRN_<PATH>` mapping of every key (types would have to be guessed from strings, and list entries addressed by index); defaulting the listen address or time zone (the PRD's A9 makes the zone the deployment's choice, and the brief's planted bug is exactly that default); allowing a path prefix in the public URL (the API's paths and the UI's hash routing assume the origin's root).
- What would change it: a deployment behind a proxy that can only serve Cairn under a path, or a second deployment needing a knob outside this surface.
