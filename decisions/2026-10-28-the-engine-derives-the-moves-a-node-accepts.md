# The engine derives the moves a node accepts now

Question (from removing the web app's copies of engine rules): the web app worked out for itself which transitions, answers and insertions a node takes, in the node menu, the row actions, the Contents checkbox and bulk actions, and the copies disagreed with the engine in four places. Where should "what can be done to this node now" live, and what does it say?

Call: each node's derived values carry `moves`, the single moves a patch of just that move would be accepted for: a row of the kind's table from the stored state; a start, a complete and a first answer only while the node is in scope; a completion only while its guards hold, with `complete_anyway` listed in its place while one fails (work only); and `insert_segment` on any node that may hold children. `skips_beneath` says whether the node skips what is beneath it. A grid test over every kind, stored state and situation (ordinary, out of scope, lacking a note) asserts that `moves` agrees with what apply accepts. Agents read `moves` in the node's derived values.

Surfaces still decide what is worth showing. A group is offered Mark done only while it is also open, since marking a group that already reads done or skipped does nothing; the primary action on a node that is no longer open is none, though the engine would take a completion of a milestone that reads done by its date. Bulk Done is still sent over work whose guards fail: the refusal names the evidence and offers the remedy in one step, so the selection need not be pre-sorted. The Contents checkbox, which sends a bare completion, appears only where `complete` is listed.

Alternatives: derive only the verbs the web needs (leaves `insert_segment`, `answer` and the table with their own copies); list every move the engine would accept for a bulk selection without regard to remedy flows (Done disabled over any work lacking evidence); keep the transition table in the generated rules for the web to compose (what produced the disagreements).

What would change it: a surface that needs a move accepted only together with other mutations in the same patch (the evidence form), which would want the engine to answer for a whole patch.
