# The revisions a commit moves besides its target's

- Question: A17, E6, and H5 say which revision a patch checks, but a few commits write outside their target: entity creates riding in a journey or route patch, a journey's hard delete (its deleted id is a deployment record), and patches to proposals.
- Call: a riding entity create (E6 lets one ride in any patch with no deployment revision check) moves the deployment revision once per commit, since it writes deployment records and A17's revision counts a domain's changes; a later patch referring to those entities names the resulting revision, and a patch referring only to entities it creates itself names none (each fixture scenario runs in a fresh deployment, and a fixture test checks the rule); the deleted-journey record does not, since it is not part of the deployment document and would only make concurrent journey patches stale. A patch to a proposal moves the proposal's revision, carried on the record it writes, which must be the base plus one; its destination's revision does not move. A journey's or route's first commit must write its fields. A published version's revision is always 1. Each stored receipt records what its commit moved (its target's revision, the deployment's, and the revision of any proposal it wrote, as applying one does) and what it wrote in the deployment, which is how a stale rejection finds what intervened, even after a hard delete has removed the events of a journey whose patch created an entity.
- Alternatives: only deployment-domain patches moving the deployment revision (a reference check could then miss a create that landed in between); moving the deployment revision on a hard delete (the deployment log keeps the event either way); the store minting proposal revisions itself (then the record the engine wrote and the one stored would differ).
- What would change it: a view of the deployment that lists deleted journeys, which would then need the revision to move.
- History: the schema brief (1.2) first settled the riding-create rule for the fixtures ("entity creates in another domain's patch advance the deployment revision"); the store brief (3.1) kept it and added the rest of what a commit moves.
