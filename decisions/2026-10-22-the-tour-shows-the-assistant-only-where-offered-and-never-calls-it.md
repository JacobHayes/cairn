# The tour shows the assistant only where offered, and never calls it

Question: how does the tour show what the assistant is for without claiming every deployment has one, or spending a model call on a fixed lesson?

Call: the step exists only when the capabilities say the assistant is offered. On the practice journey the assistant's tab shows a plainly labelled example exchange, drawn by the assistant's own transcript and composed from the same derived facts as the rest of the tour. The live assistant is never mounted for the practice journey, so no conversation starts and no provider is called.

Alternatives: always showing the step (advertises what is not there); a live first turn (cost, latency and variable output in a lesson); a fake assistant host, or swapping only the pane's content (both leave the live conversation one step away).

What would change it: a request for an opt-in live exercise after the tour.
