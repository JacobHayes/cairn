# The tour practises on a real journey, deleted when it ends

Question: while building the tour of Cairn, where does the journey a new person answers and completes live, so they can try things without harming their own work?

Call: the tour makes a real journey on whichever host the person is on, through the ordinary write path, walks it in the ordinary screens, and deletes it when the tour finishes or is skipped, with one deployment patch that deletes the journey at the revision it was read at (a journey is deleted in any status, so the tour does not archive it first). A per-user record names the journey before it is created and until it is deleted, so a tour abandoned in one tab is offered to continue or to be removed on the next visit to Home, and two tabs share one run. The tour does not keep the journey, does not publish a route, and does not mock any state.

The practice journey is made directly rather than from a published route. A route can now be deleted when nothing uses it, so a published route would not stay for good, but publishing one still puts a permanent-looking entry in every deployment's Routes list while the tour runs, and the route's header would teach versions, which the tour leaves out. The welcome card says what a route is; the end card points at starting a journey from one.

The honest costs: on the server host the practice journey is visible to everyone in the deployment for the minutes it exists, and anyone could edit it; its deletion leaves the usual record of a deleted journey and one deployment log event.

Alternatives: a second engine over a throwaway store in the page, reusing the views through an extracted navigation and storage boundary (isolated, but a large seam through code that addresses everything by URL, and a reduced app shown to the person); a shipped route published into the deployment; hand-drawn screens (they would drift from the engine); offering to keep the practice journey (ambiguous with a failed deletion, and six nodes make a poor start for real work).

What would change it: per-user visibility of journeys arriving in Cairn, which would make the practice journey private without a sandbox, or the navigation and storage boundary being extracted for another reason, which would make the sandbox cheap.
