# A node's actions hold one open form

Question (from the node actions work; PRD D1, D4, B5, B6, H5): a node's skip, keep, include, bypass, evidence, snooze and answer-anyway forms were seven independent drafts, each with its own open flag, so a restored tab could open two forms at once. A form that sent a write cleared its text when the write landed, even text typed after the send, and closing it while the write was out lost the form's view of it. What does a node's section keep, and when does a form end?

Call: one machine per open node owns which form is open. It is a tagged case (skip, keep, include, bypass, evidence, snooze, anyway, and the assign and edit-date panels), and each case carries its value, the revisions it was opened at, and a draft version that counts every change. The machine is saved as one draft under `actions:<journey>:<node>`; a restored draft is read in full (known case, known fields, values of the right type) and is discarded if any of it fails, so an unreadable draft opens nothing rather than a partial form. Sending goes to the edit manager under the edit key `node:<journey>:<scope>`; the form records the write's id and the draft version it sent. It watches that write by id, and when the write's final snapshot arrives (landed, discarded, or not held any more, which counts as an unknown outcome) the form closes only if its draft version is still the one it sent. If the person typed since, the form becomes `kept`: a neutral block that shows the text that was not sent, with Close. Closing a form never discards a write that is out; only Discard on a write that needs the person does. A refused write comes back to the form that sent it, also after a reload, and a retry of it mints a new id that the form follows. A form sent while Cairn is in version skew is not sent.

Calls inside it: the answer-anyway reason is a case of the same machine and shows the answer form on purpose, because the reason belongs with the answer being given. Old drafts (the seven per-form keys, a refused write held as a draft) are converted once at boot into the one draft, or into a rejected edit record, and the sources are removed after the replacement is stored; that conversion goes when the edit record version is bumped or a release has shipped it. Existing edit records keyed `node:<journey>:snooze:<node>` are not re-keyed: finding them means scanning raw records, and a record in flight keeps its old key until it ends.

The edit manager's node write (a submit that takes a built patch, a way to ask whether a write is held, a status that excludes a refusal) was built here because the sibling unit that owns the node write paths had not landed; whichever lands second reconciles the two.

Alternatives: keeping seven drafts and a rule that opening one closes the others (restore would still have to pick one); a form that closes on any landing (it discards typing after a send); a form that waits to send until the write lands (it blocks typing and the edit manager already makes a send safe to repeat).

Wish: the answer form's own drafts (the answer, why, a new entity's name) and the other forms in the app still clear on landing, so text typed after a send is lost there; they should follow the same version rule.

What would change it: a node section that needs two forms at once, or a form whose send must be able to be cancelled before it leaves.
