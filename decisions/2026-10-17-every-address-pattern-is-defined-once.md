# Every address pattern is defined once

Question (from the same unit): adding proposal addresses meant a fifth hand-written copy of the same path shapes (the router's, `journeyTargetOf`, `nodeOpened`'s suffix regex, the rail's regexes, and string templates in a dozen components). How are the app's addresses kept to one definition?

Call: `web/app/src/address.ts` holds a table of every pattern with the rail section each belongs to. The router registers its routes from it and gives each page the name of the pattern it matched (`AddressContext`, read with `usePage`, beside React Router's own parameters); every path is built with `pathTo(name, params)` (React Router's `generatePath`, which encodes each parameter) or a helper over it (`proposalAddress`, `proposalsAddress`, `journeyPath`, `routeCanvasPath`, `mergePath`); and screens read their parameters from the router under the table's names (`journey`, `route`, `proposal`, `key`, `edge`), asserting the ones they need. Where a node of the page opens and where closing it goes is `nodeAddress(page, search, key)`, from the matched pattern and its parameters, and every node link and key asks it through `useNodeAddresses()`; nothing reads a pathname to learn what page it is on. The rail, which sits above the pages, lights its section with React Router's `matchPath` over the same table. Deleted: `journeyTargetOf`, `addressOf` and its trailing-slash trimming, the suffix regex in `nodeOpened` (and `nodeOpened` itself), the rail's regexes, the `/proposals/${id}` strings, and the literals for `/me`, `/entities` (and its `?merge=`), a route's page and a route version's `?version=`.

Alternatives: leave the patterns where they are and add proposals to each (what made the previous call hard to see); generate the router from the API's paths (the app's paths carry views and screens the API does not have).

What would change it: a pattern the table cannot express (a splat, an optional segment), or a page whose node addresses depend on more than its pattern, its parameters and its query, which would provide its own `NodeAddresses` instead.
