# Proof scripts stay outside the repository

- Question (from the owner's call after the proof scripts of landed work were deleted): AGENTS allowed a script beside a proof page to regenerate its media or value table, and `web/app/playwright.proof.config.ts` ran Playwright specs kept in `web/app/proof/`. Every such script was only ever run by the change that wrote it; once it landed nothing ran it, so it rotted against the code it pictured, and the cleanup that removed them found none worth keeping. Should a change still commit the script that took its proof's media?
- Call: no. A proof page and its media (PNG, short WebM) are committed; the script that took them stays in the change's scratch directory, outside the repository, and is not kept for re-running. A proof records what its change shipped, so its media never need regenerating against later code. `mise run proof <dir>` runs the `*.proof.ts` specs in a directory outside the checkout through the proof config (which now takes that directory from `CAIRN_PROOF_DIR` and refuses to run without one): it installs the packages, builds the browser host's module (and, with `CAIRN_E2E_BINARY=1`, the web build the server host serves), and the config's `web/app/tsconfig.proof.json` maps `@playwright/test` to the checkout's copy so a spec outside it resolves the package (as CommonJS or ESM); the spec imports the browser tests' helpers by their absolute path under `web/app/e2e/`. The `web/*/proof` entry in `tsconfig.json` goes, and so does the proof config's viewport, which every project's device settings overrode.
- Alternatives: keep scripts beside proof pages (code nothing runs, which rots unexercised and costs review in every change that adds one); keep proof specs in `web/app/proof/` but uncommitted (an ignored folder inside the checkout is lost with the workspace, and a spec there would be type-checked and linted as repository code); `NODE_PATH` instead of the mapping (Node ignores it for a spec under a `package.json` of `"type": "module"`); a symlink to `node_modules` beside each spec (a step every builder must remember, in every scratch directory); no task, only the documented Playwright command (the module and web builds the old per-proof scripts each repeated).
- What would change it: a proof whose media must be retaken against later code, say a page that tracks a living screen rather than a change. Then its script would be a check something runs, kept beside what it pictures.
