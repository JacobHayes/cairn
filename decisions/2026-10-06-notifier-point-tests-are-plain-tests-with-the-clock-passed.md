# Notifier point tests are plain tests with the clock passed in

- Question: brief 4.1 asked for the notifier's coalescing and initial revisions as `#[patina_dst::test]`s (PRACTICES, Simulation: point tests). That attribute runs each test through `cargo patina test`, so it needs the `cargo-patina` binary at test time; CI's `check` jobs skip building it (`MISE_DISABLE_TOOLS`, brief 1.3), and PRACTICES keeps the core ladder free of it.
- Call: the notifier reads no clock and starts no timer: the caller passes its monotonic time to `Subscription::take`, which answers when to come back, and awaits `Subscription::ready`. Each interleaving that matters (a commit between registering and seeding, either side of the store's read; several commits in one interval; out-of-order and repeated publishes; the subscriber limit; a wake on a watched publish) is then an ordinary deterministic test in `crates/store/tests/notifier.rs`, run in rung 2. A seed sweep would add no schedule these tests do not already spell out.
- Alternatives: `#[patina_dst::test]`s (every `check` run, and CI's, would need `cargo-patina` built first, minutes per run); a notifier with its own timer thread (not runtime-free, and its timing could only be tested by sweeping).
- What would change it: the `check` jobs installing `cargo-patina`, or a notifier that must own its timing (several processes, `Later`).
