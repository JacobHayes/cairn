# The layout is hinted by the view's last positions; a fresh view lays out from its graph alone

- Question: ARCHITECTURE (Web UI, Canvas) lays the canvas out with ELK "in interactive mode with the previous revision's positions as hints" and caches positions per revision; C15 asks that the same graph lay out identically and small edits move few nodes, and the brief asks for a stated fraction. ELK's interactive layering and crossing minimization are not hierarchy-aware: on the nested canvas (`hierarchyHandling: INCLUDE_CHILDREN`, which C3's one-canvas view needs for edges across levels) interactive crossing minimization is refused (`UnsupportedGraphException`), and interactive layering alone moved every one of the vendor evaluation's 27 nodes when one was added. And a layout that depends on the previous revision depends on a tab's history, not only on its graph.
- Call: layered layout with network-simplex layering, fixed seed, and ELK's semi-interactive crossing minimization fed the view's latest positions (`elk.position`) as hints, so each layer keeps its order across an edit. A layout is cached per domain and view (kinds shown, container, relevance shown) by everything it reads (each card's size, parents, edges), not per revision: a revision that changes nothing the layout reads lays out nothing, and a layout hinted with its own positions is a fixpoint. The same graph with the same hints lays out identically; a fresh view (no hints, as after a reload) is a function of its graph alone. The stated bound: adding one node or one requirement to the vendor evaluation moves fewer than a quarter of its nodes within their containers (a container that slides carries its contents, which count once); measured at most 6 of 27 on five edits in the unit tests and on the fixture in the browser.
- Alternatives: ELK's model order (`considerModelOrder`, tree order) with no hints, the same layout in every tab for a revision, but up to 13 of 27 nodes moved on the same edits; interactive layering (every node moved); positions stored with the graph (pinned positions are Later, PRD C15).
- What would change it: people noticing two tabs drawing one revision differently after a session of edits (then model order, accepting the larger moves), or ELK gaining hierarchy-aware interactive strategies.
