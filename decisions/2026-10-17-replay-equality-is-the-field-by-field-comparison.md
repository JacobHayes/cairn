# Replay equality is J3's field-by-field comparison

- Question: J3 said the replay harness "compares it field-by-field to stored state, under a scenario matrix". `2026-10-17-replay-runs-inside-the-shared-apply-helper.md` dissolved the matrix and said its field-by-field comparison "is gone", replaced by one `assert_eq!` on the records in `support::apply`. Found by the audit of the units that landed that day: does the code still do what J3 asks, or does J3 need a field-by-field walk back?
- Call: the code meets J3, and J3 is reworded only where it named a structure that no longer exists. `Records` and everything under it derive `PartialEq`, with no hand-written impl anywhere in `engine` or `schema`, so the one equality compares every field of the replayed records with every field apply produced: that is a field-by-field comparison, and a drift in any field fails it. What the old harness added was a per-field report of where the drift was, which `assert_eq!`'s debug diff of both sides also gives. J3 now says the comparison runs "after every accepted step of the scenario tests, which cover (...)" instead of "under a scenario matrix (...)": the scenario list is unchanged, and "matrix" no longer suggests one file holding them. The stale "matrix" wording in the fixtures README, the test comments, the walkthrough examples and a test name was replaced in the same change.
- Alternatives: restore a field-by-field walk (a second comparison that fails on exactly what the equality fails on); drop "field-by-field" from J3 (it loses the requirement that no field escapes the comparison, which a future hand-written `PartialEq` could break).
- What would change it: a hand-written `PartialEq` on any record type, or a field excluded from equality, would make the equality weaker than field by field; the comparison would then need to name the fields it checks.
