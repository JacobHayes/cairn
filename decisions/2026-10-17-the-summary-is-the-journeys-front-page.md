# The Summary is the journey's front page

Question: what does the page a journey opens on say first, in what order, and from which values?

Call: in order, where the journey stands (what is left in scope, counts by display state, the final milestone), what is wrong (overdue, short of days, stale, stalled, each with its reasons), what to do (what waits on the viewer, decisions that can be made now, the rest of the frontier, decisions still waiting and on what), then context. It reads only values Cairn already derives and adds no engine concept.

- One row per node across the action panels: the sets are claimed in that order, so a node never appears twice.
- "Waiting on you" is work the viewer owns, not any participation: this page asks who holds the pen.
- Only the `final` milestone is called the end; with none, the page names the next milestone. A past date is late, never a completion.
- Blocked work says what holds it, from its own blockers, which are exact; the page does not count what waits behind it.
- A completed or archived journey says what it left unfinished, so the page never reads as a queue; an archived one offers no actions.

Alternatives: an engine field counting what each blocked node waits behind (exact for agents too, but a new engine concept); every participation under "Waiting on you".

What would change it: someone asking what blocked work waits behind, which would bring the engine field.
