# Replay runs inside the shared apply helper, not in a scenario matrix

- Question: the engine tests had a scenario matrix (`engine/matrix.rs`) with its own replay harness: one entry per scenario, each rebuilt from its events after every step and compared field by field. Most of its scenarios repeated tests in the area files, and only the scenarios listed in the matrix were replayed. PRACTICES (Replay harness) asks that every scenario replay. Should the harness stay a separate file?
- Call: dissolve it. `support::apply` wraps `cairn_engine::apply` and, for every accepted patch, asserts that `replay(before, events)` equals the records apply produced. Every engine test that applies a patch (the support helpers, `apply`, `domains`, `plan`, `limits`, `format`, `requires_note`, `rationale`, `level_filters`) goes through it, so every accepted step of every scenario in the suite replays, not only the matrix's. Generated and cost tests keep their own apply calls (the property tests assert replay themselves; the cost tests run at the size limits, where a replay per step would dominate the run). The matrix's field-by-field comparison is gone: one `assert_eq!` on the records fails on the same drift. Scenarios the area files already covered were deleted, the assertions only the matrix made were moved into those tests, and the rest moved to the area file they exercise. The vendor tables (frontier, rank, decision points, due dates) were deleted because `fixture_readme.rs` reads the README's own tables. PRACTICES now says "scenario tests" with no single file and says where replay runs. A planted break (replay skipping the answer events) failed 130 tests across the suite.
- Alternatives: keep the matrix and add replay to the helpers too (two ways of doing one thing); replay only in the matrix (the previous state: most steps never replayed); a replay check per test file (many copies to forget).
- What would change it: a replay cost that makes the suite slow (replay is one clone of the records plus one write per delta entry, small beside apply), or a need to compare field by field to name what drifted, which a diff of the two records already shows.
