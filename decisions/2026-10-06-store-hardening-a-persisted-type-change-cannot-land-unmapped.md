# Store hardening: a persisted type change cannot land unmapped

- Question: engine briefs added persisted fields (`NodeState.skip_reason`, `LocalEdit::Shape`) while the Turso backend was built in parallel from an older schema; Turso silently dropped one and rejected the other, and only a sampled property round trip caught the second. How does a schema change fail until both store backends map it?
- Call: two gates, recorded as a rule in PRACTICES (Shell: conformance and integration). (1) Compile time: every Turso codec that splits a persisted value into columns destructures it with no `..` and builds the loaded value as a struct literal (nodes, payloads, roles, kinds, resources, retired keys, every state record, headers, entities, proposals, events, receipts, auth and conversation records); matches over persisted enums name every variant (memory's record and key dispatch, `backend::graph_records`, which both backends' graph copies replay, destructures `Graph`, `RetiredKeys`, and `JourneyState`). Whole-value JSON columns (conditions, date rules, choices, answers, bypasses, mutations, review items, subjects, deltas) need none. Unit enums keep serde names in text columns: serde's derive names every unit variant, so a new one round-trips with no store change, and a data-carrying one fails the write. (2) Deterministic coverage: `cairn_store::build::every` builds each persisted type with every optional field filled and every variant held (from the schema's `ALL` lists, or a successor chain written as an exhaustive match, so a new variant does not compile until it joins), and a cleared counterpart with every option empty, flags at their defaults, and variants rotated; `conformance::every` puts the filled value, puts the cleared one over it, puts the filled one back, removes each record by key, and compares each backend's load with the value at each step. The randomized round trip stays for combinations; the strategies now draw every `NodeField` and `State`. Turso now writes a node's own flags non-null and reads a null one as its default, so rows written before stay readable; its loads reject a column the node's kind or answer type cannot have and child rows with no parent row.
- Proof: (a) a planted `NodeState.paused_on` fails to compile: `error[E0063]: missing field paused_on in initializer of cairn_schema::NodeState --> crates/store-turso/src/state.rs`, `error[E0027]: pattern does not mention field paused_on --> crates/store-turso/src/write_state.rs`, and the same E0063 in `crates/store/src/build/every.rs`. (b) Turso writing `skip_reason` as always null still compiles, and `conformance::every_field_and_variant_loads_back_equal` fails on Turso (`panicked at crates/store/src/conformance/every.rs`, the loaded journey's node states differ), while the older `a_journey_round_trips_every_record` passes. (c) Leaving `description` out of the journeys upsert fails `a_cleared_overwrite_loads_back_equal_and_every_record_removes`. All three were restored.
- Alternatives: a serde-shaped column map with a runtime check that every written key has a column (Turso's previous node codec: it rejects an unmapped field only when a test writes one, and drops nothing it cannot name); whole-graph JSON columns (no field can be dropped, but no index or search columns); a schema-wide variant list such as `strum` (a new dependency for what a chain gives).
- What would change it: a third backend, which takes the same rule; a schema change that needs a column migration, which still needs its numbered migration beside the codec.
