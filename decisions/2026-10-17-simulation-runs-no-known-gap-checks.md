# Simulation runs check no known dependency gap

- Question: should `mise run sim` keep a leg that re-proves a known gap in a pinned dependency (patina or the store's database library)?
- Call: no. Patina and the database library are pinned (`mise.toml` revision, `Cargo.lock`), and such a leg exercises only the dependency, never Cairn's product code. On the same binaries it gives the same result every night and can change only on a version bump. Each testbed keeps its audit leg and its symbol allowance, since every run needs them. A gap in a dependency is recorded where its owner reads it (a patina issue, or a `[patina]` file in `decisions/`); whoever bumps the dependency reads those and retests by hand. A test that injects a fault and asserts the dependency still misbehaves tests no Cairn behaviour and does not belong in the store's cases either.
- Alternatives: keep the legs as a bump alarm (a nightly cost and a failing leg that means "good news, update the notes", for a bump that is a deliberate act anyway); move the reproducers to a bump-time task (still code to maintain for something checked a few times a year).
- What would change it: a gap that Cairn's own code reaches, which belongs in a test of that code, not in a leg about the dependency.
