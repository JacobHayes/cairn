# Simulation runs check no known gap

- Question: `mise run sim` ended each testbed with legs that failed once a known gap stopped reproducing: the durability testbed's leg 7 (a retried open panicking in Turso's page cache, swept over 64 seeds, and no crash leaving part of a Turso log frame) and the multiplayer testbed's last leg (patina refusing to run beside Turso's unsupported symbols, a site label holding a space, an `always!` violation leaving no trace). Should the nightly run keep re-proving them?
- Call: no. Patina and Turso are pinned (`mise.toml` revision, `Cargo.lock`), and those legs exercised only patina or Turso, never Cairn's product code: the retried-open panic was reached only through the testbed-only `--open-attempts` flag (Cairn's server exits and is restarted instead of retrying an open in-process). On the same binaries they gave the same result every night and could change only on a version bump. Removed with them: the legs, `--open-attempts` and the open retry loop in the durability testbed, and the reproducer binaries in `testbeds/multiplayer/gaps/` with their lint exception. Kept: the audit leg of each testbed and its symbol allowance (every run needs it), and the testbed READMEs' findings and gap reports as history. The gaps stay recorded as patina issues outside the repository and in the `[patina]` and `[turso]` files in `decisions/`; whoever bumps patina or Turso reads those and retests by hand.
- Alternatives: keep the legs as a bump alarm (a nightly cost and a failing leg that means "good news, update the notes", for a bump that is a deliberate act anyway); move the reproducers to a bump-time task (still code to maintain for something checked a few times a year).
- What would change it: a gap that Cairn's own code reaches, which belongs in a test of that code, not in a leg about the dependency.
