# Cost tests stay at the limits in every check; their independent derives run side by side

- Question: the engine's cost tests took about 20 s of rung 3 in every local check. Could they run on smaller inputs locally, with the full size only in CI, the way property tests run fewer cases locally?
- Call: no. They are not scaling tests that compare two sizes; each checks an absolute operation budget on the generated graph at the limits (`node_count_max` nodes at the depth limit, over 300,000 date constraints) and asserts it is that graph. A budget linear in the input's size can hold on a small graph while a superlinear term breaks it at the limit, so a smaller input proves less, and PRACTICES (the validation ladder, rung 3) asks for cost tests at the limits. Property tests are different: fewer cases sample the same space less, rather than a different space. The wall time came from two tests that ran independent derives at the limits one after another: priority's three readings (about 16 s) and the upgrade's draft, apply, and the rename it is compared with (about 12 s). Those now run on threads within the test, so each test takes its longest part. The cost tests take 8.7 s instead of 20.3 s and rung 3 17 s instead of 25 s, with every budget, size assertion, and printed figure unchanged.
- Alternatives: a smaller generated graph locally and the limits in CI (a weaker local guarantee, and a second size to generate and keep honest); splitting each test into one test per reading (renames tests and repeats setup); an optimized engine in the dev profile, which tests build with (weighed on its own, since it changes every build of the engine).
- What would change it: a cost test written as a comparison of two sizes, which could then run small locally; or rung 3's wall time dominated by one derive that cannot be split.
