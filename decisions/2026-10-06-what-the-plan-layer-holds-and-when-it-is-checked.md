# What the plan layer holds, and when it is checked

- Question: F5's plan layer is "pins, rules, estimates, containment, stage bounds, dependencies", with no actuals and no today, checked "during validation of any patch that changes constraints or pins" (ARCHITECTURE). Neither says whether relevance and effective skip shape it, whether the date answers rules measure from and the journey's `created_at` are fixed in it, or how a patch is known to change constraints.
- Call: the plan layer is the date network over 2.2's pruned graph (constraints of not-relevant nodes dropped, those through undecided nodes kept and marked conditional, skipped work at zero duration), seeded with the pins of in-scope nodes (direct, and those `feeds_milestone` answers in effect give, E3) and with each date answer in effect fixed on its own answer instant. `created_at` is a fact, like an actual: it enters only the execution layer. The check runs on every graph a patch writes, once the graph stages pass (it derives relevance, which needs a graph that holds every other invariant): in the apply pipeline, an entity merge's check of the journeys it touches, the post-apply reverify, `Graph::new`, and `from_file`. A graph that breaks a structural invariant is reported for those and not for its chains. Positive cycles are searched first; pin-against-pin conflicts only when there are none, since bounds over a positive cycle mean nothing.
- Alternatives: the full structural network (would reject contradictions in branches that do not apply); `created_at` fixed in the plan (a rule relative to it could then reject a patch on a fact); checking only patches that classify as touching dates (a transition that skips or reopens work changes durations, a force include or an answer changes which constraints apply, so the classification would have to re-derive anyway).
- What would change it: users reopening skipped work and finding the reopen rejected because full estimates no longer fit the pins, which would argue for full durations in the plan layer.
